# v0.10.2 · 仪表盘权限分级重做 —— 能力集合 + 偏序判定 + 功能级门禁

> 发布日期：2026-11-28 · 里程碑：**M1** · versionCode 48

## 概述

按《Abyss-Tools-仪表盘权限分级升级实现方案》重做 PR #30 首版设计：不再用「五档枚举 ordinal 比大小 + 每工具标 requiredTier」，改为「能力集合 + 偏序判定 + 功能级门禁 + 多模式」四件套。能力集合是唯一事实源，档位只是派生出来的展示标签；功能放行一律 `required ⊆ capabilities`。27 条工具的权限矩阵与《Abyss-Tools-权限矩阵.csv》逐条对齐。

## P1 · 首屏权限可读（FEAT-038）

- 仪表盘状态区：五档文字徽章（普通 / 进阶 / 高级 / abyss-max / abyss-ultra）+ 普通用户旁常驻小问号；点击弹出「权限档位说明」对话框，首行即「当前未授予任何权限，只能启动极少功能」，附五档说明表与「去授权」
- 五枚可交互能力片：Shizuku / 无障碍 / 设备管理 / 安装未知 / 悬浮窗 —— 圆点表态 + 短标签，点击直达对应授权页（Shizuku 按运行态分流「打开 Shizuku / 立即授权」）
- 「本机理论可达最高档」提示：Android 15+ 侧载受限设置 / Android 16 高级保护时如实说明，不卡流程
- 旧 `StatusChip`（8dp 圆点、40+ 调用点）零改动；新组件独立落在 designsystem

## P1 · 探测层修正（ARC-011）

- 修正 Shizuku root 误判：首版用本进程 `id -u` 推断服务端身份（恒为 App 自身 uid），现改用官方 `Shizuku.getUid()`（0 = root / 2000 = shell）
- 修正 Dhizuku 误判：首版读跨包组件启用态（与授权无关），现改为 `init ∧ isPermissionGranted ∧ dpm.isDeviceOwnerApp(provider)` 三方交叉验证，接入 Dhizuku-API 2.5.3（Maven Central）
- 变体不再硬判：`Running` 扇出 `serverUid` / `suiAvailable` / 已装变体 / 「疑似」提示，仅作展示
- 无障碍双路交叉（Secure 设置 ∧ AccessibilityManager 已绑定），不一致保守判 false 并写人话原因
- 新增零策略 `AbyssDeviceAdminReceiver` 与最小能力集 `AbyssAccessibilityService`（`isAccessibilityTool=false` 如实声明，只做前台包名感知 + 手势代点原语）
- 快照刷新：Shizuku binder / 授权回调 + 无障碍 ContentObserver + 设备管理员 onEnabled/onDisabled + onResume，四路不跨会话缓存

## P1 · 功能级门禁与多模式（FEAT-039）

- 仪表盘快捷工具与功能页全量 27 张卡统一 `GatedToolCard`：锁定行显示锁形 + 「需 Shizuku、无障碍」短文案（按缺失能力而非档位，避免「需 abyss-max」误导）
- 锁定卡点击进门禁说明页（不再静默无响应）：缺失能力 + 去授权 + 多模式表（✓ / ✗）+「以受限模式进入」（任一模式门槛已满足时，如终端的查看历史 = 零权限）
- 返回栈新增 `ungated` 标记并随 token（`tool!:`）序列化，进程重建后语义不丢
- 快捷工具 count / listOf 双源收口为 `QUICK_TOOL_IDS` 单一数据源

## P2 · 伪装五级模式（FEAT-040）

- 机型伪装页新增 low / medium / high / max / ultra 模式卡，每级绑定能力集合并如实标注「生效 / 仅档案 / 不可用」：ultra 三项齐全也只到「仅档案」（设备策略面板未落地），不把「导出了档案」显示成「已生效」
- `ShizukuGuardBanner` 保留原签名，新增泛化 `CapabilityGuardBanner`，四件套页面行为零变化
- 新手引导新增「权限档位中心」步（七步 → 八步），就绪页显示五档结果与「还差什么」

## P3 · 规格与测试

- 新增规格 4 份（`ARC-011` / `FEAT-038` / `FEAT-039` / `FEAT-040`），修订 8 份（`ARC-009` / `ARC-010` / `SHL-004` / `FEAT-001` / `FEAT-027` / `FEAT-031` / `N-DO-001` / `N-ICON-001`），`QA-008` 登记追溯，规格总数 230 → 234
- 纯 JVM 单测新增 25 例：五档判定表、ultra 缺无障碍仍为 ultra、特殊授权不升档、27 条矩阵契约、零权限工具集、伪装五级真值
