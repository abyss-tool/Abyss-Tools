# v0.10.3 · Linux 插件解耦 Spec Set v1.4 入仓 + 宿主自消费通道 getInternalSession

> 发布日期：2026-11-28 · 里程碑：**M0（Linux 底座 B 方案）** · versionCode 49

## 概述

按《深渊工具-Linux插件解耦设计规格.zip》（Spec Set v1.4 最终裁定稿）把主仓侧的 Linux 插件解耦工作落到位：规格集 v1.0 → v1.4 同步入仓（保留独立 `abyss-plugin-linux` 底座插件的 B 方案裁定），并补齐主壳唯一缺失的机制 —— 主壳自己的功能模块消费 Linux 底座的 `PluginBroker.getInternalSession()` 宿主自消费通道（ARC-104 §4）。

## 规格（docs）

- `11-Linux插件解耦` 由 v1.0（23 份平铺）升级到 v1.4（31 份，按套件官方布局分子目录：00-总纲 / 01-架构 / 02-Linux插件 / 03-应用构建器 / 04-数据契约 / 05-安全工程 / 06-任务方案 / 07-服务器插件）
- 新增 8 份：`SRS-103`（RAM 口径留痕）/ `SRS-104`（300MB = 签名后 APK 字节数，口径纠错）/ `SRS-105`（A′ 单 APK 全内置，留痕）/ `SRS-106`（B 方案最终裁定：保留独立底座插件）/ `ARC-104`（三类调用方接入契约 + getInternalSession + M0 门禁）/ `LIN-006`（UML 真内核域）/ `LIN-007`（常驻会话与端口转发）/ `SRV-100`（手机变服务器插件预留）

## 宿主自消费通道（ARC-104 §4，core:plugin）

- 新增 `PluginBroker.getInternalSession(request, index, installed, sessionId)`：主壳内部模块（如未来的 `internal:terminal`）可拿到受限 `ILinuxSession` 代理所需的令牌 —— 此前 `CapabilityBinder.isConsumerPlugin()` 白名单会把宿主自己以 `E_DIRECT_BIND_DENIED` 拒掉
- 只跳过「消费方白名单」一项，其余照做：requesterId 审计标识校验（`internal:<id>`）、宿主自校验（包名 + 发布者指纹，归一化比对）、能力 ∈ 底座 `provides`、复用 `DependencyResolver`（minHost / minApp / ChannelPolicy）、底座必须已安装（否则 `E_RUNTIME_UNAVAILABLE` + 一键安装引导，绝不谎报可用）
- `SessionGrant` 新增 `scope`（PLUGIN / INTERNAL）与 `requesterId` 字段（默认值向后兼容）；`SessionGrantIssuer.issueInternal()` TTL 收紧到 ≤60s（插件会话仍 300s），nonce 一次性、可撤销语义不变
- 审计分账：`AuditEvent(requesterId, sessionId, capability, outcome)` → Android 侧接 `DiagnosticsLog`（新增 `Kind.PLUGIN_SESSION`）
- `ServiceRegistry.pluginBroker` 手动装配（宿主包名 + `PublisherSignatures.PINNED_SHA256`）；指纹常量配错即构造失败（fail-closed）

## UI（ARC-104 AC-005）

- 工具详情页的插件卡按底座安装态改写：`abyss-plugin-linux` 未装时，底座条目与所有依赖它的插件入口显示「需（先）安装 Linux 运行环境」，按钮直达底座插件详情，不再出现半可用状态
