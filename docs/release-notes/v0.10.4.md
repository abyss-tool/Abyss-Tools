# v0.10.4 · 深挖缺陷第三轮 —— 令牌引擎并发收口 + 门禁粘性 + 探测线程治理

> 发布日期：2026-11-28 · 里程碑：**M0 收尾（深挖加固）** · versionCode 50

## 概述

三路并行深挖（core 契约层 / app 探测与 UI 链 / 插件仓 G-1 门禁）定位 23 处缺陷，本轮修复主仓侧 15 处（P1×3 + P2×12）：会话令牌引擎的并发与泄漏三连（nonce 竞态 / 无界增长 / 代际丢更新）、工具页门禁的会话内粘性（能力中途丢失不再丢弃用户表单）、权限探测下沉后台线程（冷启动 ANR 面），以及门禁说明页 / 仪表盘 / 伪装模式卡的一批 UI 硬伤。

## 令牌引擎（core:plugin，NB-25）

- `SessionGrantIssuer.verify` 的 nonce 消耗由「读-判-写」改为 `putIfAbsent` 原子操作 —— 并发重放同一 grant 只放行一次（旧实现两线程同拍可双双 Valid，单次使用承诺被穿透）；撤销检查移到消耗之后，在途调用不再穿透已撤销会话且不留孤儿条目
- `usedNonces` / `activeGrants` 增加按 TTL 的机会性清扫（每次签发 / 校验顺带收缩）—— 长驻宿主按 60s 续签节奏滚动签发时两表不再无界增长；`revoke` 的 nonce 收缩改为无条件执行（二次撤销不再跳过）
- 宿主代际改 `AtomicLong`：并发 `invalidateAll`（灰度关停 + 回收同拍）不再丢翻转
- 新增 `SessionGrantIssuerConcurrencyTest`（并发 verify 竞态 / 撤销闭环 / TTL 清扫 / 代际翻转四锚）

## 门禁与越权（core:plugin，NB-26~28）

- `PluginBroker.getInternalSession` / `CapabilityBinder.getCapability` 预校验空 sessionId —— 旧实现会把 `SessionGrant` 构造器的 `require` 异常穿透 Binder / UI 调用栈（违反 FR-002），现在返回人话 `E_GRANT_INVALID`
- 内部会话补 since 门槛：底座已装版本低于索引 `provides[].since` 时拒签并引导升级（`E_DEP_VERSION`）—— 修复「索引升级后本地旧底座看似提供能力」的假可用路径；since 形态非法同样 fail-closed 拒签
- `CapabilityBinder` 新增能力声明硬校验：白名单消费方必须在索引 `depends` 里声明所请求的能力才签发 —— 白名单只是「是消费方」不是「任意能力通行证」（HOST_API v3 多能力时代的越权锚）

## UI 与探测链（app / feature / designsystem，NB-29~34）

- 权限探测下沉 `Dispatchers.Default`：冷启动与每次 onResume 不再在主线程执行约 8 次 PackageManager 查询与 Dhizuku 跨应用 ContentProvider 调用（低端机卡顿 / ANR 面）；探测失败仍 fail-closed 空快照
- 工具页门禁会话内粘性（AbyssBackStack 门禁通过标记）：进入功能页后能力中途丢失（关 Shizuku / 无障碍被杀）不再静默换回门禁说明页 —— 用户表单态与在途任务不再被销毁，页内守卫横幅与网关二次校验继续兜底；进程重建后标记丢失，以实时快照重裁决（fail-closed 不变）
- 机型伪装表单改 `rememberSaveable`：旋转 / 深浅色切换不再丢未应用的档位 / 档案 / 设备名 / 蓝牙名 / 自定义三件
- 伪装模式卡：成功切换后清除上一枚不可用模式的「缺 …」提示行；「当前生效」标签不再重复渲染两份
- 仪表盘能力片：探测层原因（如「无障碍已登记但服务未连接」）追进 TalkBack 朗读文案（此前该数据在仪表盘侧丢失）；能力片 / 五档表行 / 模式行 / 锁定徽标合并语义焦点，同段信息不再读两遍
- 门禁说明页落地 `ToolAccess.guide` 首个消费点：PLUGINS 导向的工具给出「安装 Linux 运行环境 / 查看承载插件」主行动（与「去授权」互补），字段不再是无消费者的死数据
- 权限矩阵口径留痕：含特殊授权（安装未知应用）的工具最低档位以 ARC-011「特殊授权不升档」裁决为准（代码派生 SENIOR，矩阵 display_tier 标注 ABYSS_MAX 属上游资料口径差异，已在 ToolCatalog 注明）
