# v0.10.1 · 深挖缺陷第二轮（NB-4~NB-24）—— 三路并行扫全仓

> 发布日期：2026-11-27 · 里程碑：**M1（收尾维护）** · versionCode 47

## 概述

「更艰难的找 bug」第二轮：三路并行深扫（core 四模块 / 八个 feature 模块 / app 壳与剩余模块）共确认 19 处真实缺陷 + 1 处发布链时序缺陷，全部修复并逐条标注 NB 编号（NB-4 起，衔接 v0.9.22 的 NB-1~NB-3 批）。

## P1 · 崩溃与功能失效（4 处）

- NB-4：更新下载 416 自愈路径不可达 —— 残留 `.part` 长于远端资产时（资产重发/回滚）每次重试都带越界 Range → 下载死循环；现在就地截断 part 后无 Range 重发一次（ResumePlanner 的 RESTART 语义终于可达）
- NB-13：电量守护停止时守护线程未捕获 `InterruptedException`（runBlocking 中断路径）→ CrashGuard 链到默认处理器 → 进程死亡；reassert 与 sleep 同受保护 + onDestroy 有界 join + 命令间检查停止位（「先停后 reset」竞窗收窄到至多一条在途调用）
- NB-14：信号覆盖层 START_STICKY 进程重建后静默回落默认「5G·4/4 格」—— companion spec 随进程死亡丢失，现从 DisguiseSettings 磁盘真相源恢复
- NB-15：进程死亡恢复应用详情页被静默丢弃 —— `LaunchedEffect` 的 key 在 await 前被置 null，Shizuku 状态回调必触的重组把挂起中的恢复 effect 取消；改 `LaunchedEffect(Unit)`

## P2 · fail-closed 纪律与并发（10 处）

- NB-5：插件 `minApp` 坏版本号静默跳过宿主门槛（fail-open）—— PluginInstaller 与 DependencyResolver 双处改拒绝
- NB-6：`CappedFdReader` 对同一 OS 描述符双重 close（pfd.use 叠加 FileInputStream.use）—— 并发下 fd 号被复用时误杀无关流（OkHttp socket / 其他 exec 管道）；改 `detachFd()` 所有权移交
- NB-7：诊断日志 offer/poll + 独立计数器漂移（同 NB-3a 模式）—— 队列自身水位为准
- NB-8：补丁 DELETE 动作失败静默吞掉 → 账本升版但文件仍在的自相矛盾态；现抛错走既有回滚
- NB-9：摘要校验失败的插件 APK 残留缓存位且被 UI 继续解析 —— 就地删除（与主壳更新语义对齐）
- NB-10：DNS 失败分类恒漏（message 不含 UnknownHost 字样，类名才是可靠信号）
- NB-11：通道漂移守卫对类型混淆 JSON 抛裸 `IllegalArgumentException` 逃逸契约
- NB-12：`SessionGrantIssuer` 两张表无同步（Binder 池 + DeathRecipient 并发面）—— ConcurrentHashMap
- NB-17：蓝图执行历史并发读-改-写丢记录（闹钟协程 × 手动运行）—— 进程级锁
- NB-16：隔离空间创建名粘贴换行 → `require` 在点击处抛 → 闪退；入口滤除

## P2 · UI 语义（5 处）

- NB-18：终端 400 行窗口裁满后自动滚动永久停摆（size 恒定不再触发）—— append 代数为 key
- NB-19：仪表盘 Loading/Error 展示编造的插件计数（`?: 3` / `?: 13`）违反 UiState 三态纪律 —— 如实「— / 读取中 / 索引不可用」
- NB-20：新手引导旋转丢步（七步门回到第 0 步）—— step 存 saveable
- NB-21：脚本实验室保存非点击时刻快照（busy 期间可继续输入）
- NB-22：更新失败面板「知道了」按钮恒禁用且点了也是重试 —— 按可恢复性分流

## 发布链时序（NB-24）
