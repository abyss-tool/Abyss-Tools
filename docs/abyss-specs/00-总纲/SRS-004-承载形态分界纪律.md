## 1. 目标与范围

v0.8.0 收紧后的分界：只有「自带完整引擎」的能力才插件化，其余一律内置主壳；~~插件永远是导航第一分类~~（v0.9.12 FEAT-034 修订：引擎级插件能力由底部导航「插件」独立 tab 承载，工具目录只登记主壳内置 / 插件承载的工具行）。

## 2. 现状锚点（克隆研究实测）

- `Abyss-Tools/core/common/src/main/kotlin/com/abyss/tools/core/common/ToolCatalog.kt`
- `Abyss-Plugins/docs/ADDING_PLUGINS.md`

> 研究口径：2026-11-21 对 `github.com/abyss-tool` 组织下 19 个公开仓库（主仓 / 发布仓 / 插件中心 / 13 归档插件仓 / 3 引擎级插件仓）全量拉取，共 511 个文件；主仓 296 个文件、约 22 个 feature 模块。

## 3. 功能需求

| 编号 | 需求描述（原子、可验证） |
|---|---|
| FR-001 | 新插件必须自带完整引擎（构建底座 / 病毒特征引擎 / 整机虚拟机级别），否则直接实现进主壳。 |
| FR-002 | BUILT_IN 条目必须在 settings.gradle.kts 有对应 feature 模块与真实功能页。 |
| FR-003 | PLUGIN 条目必须带 pluginId 且该 id 存在于 plugins.json。 |
| FR-004 | FRAMEWORK 条目必须在路线图中有明确里程碑，不得长期无主。 |
| FR-005 | 归档能力不得再以插件形式复活，避免插件中心碎片化。 |

> 纪律：每条 FR 必须至少被一条 AC 或一个自动化用例覆盖；下表 AC 为关键验收条件，完整覆盖关系由 `QA-008 需求追溯矩阵` 与 spec-lint 登记校验。需求变更需同步更新本文件与对应的测试夹具（`src/test/resources` 为通道契约镜像）。

## 4. 契约与接口

```kotlin
enum class ToolStatus(val label: String) {
    READY("可用"), BUILT_IN("内置"), PLUGIN("插件承载"), FRAMEWORK("路线图中")
}
```
v0.9.5 实测：PLUGIN = 3（app-builder / virus-guard / virtual-machine）；FRAMEWORK = 4（battery-doctor / code-editor / privacy-guard / time-shift）。

## 5. 失败语义与边界

- 坏数据 / 非法版本 / 路径穿越 / 签名不符一律 fail-closed 拒绝并给人话错误，不猜测、不静默降级。
- 远端数据统一走 `UiState`（Loading / Error / Data），加载中禁止展示假数据。

## 6. 验收标准

| 编号 | 验收条件 |
|---|---|
| AC-001 | ToolCatalog.tools 中每个 PLUGIN 条目的 pluginId 均能在 plugins.json 命中。 |
| AC-002 | 每个 BUILT_IN 条目都能在 AbyssRoot 找到路由分支。 |

> 验收方法：纯 JVM 单测（`./gradlew test`）/ CI 门禁脚本 / 真机回归清单（Android 15 与 16 各一台）/ 通道清单校验，按单元性质择一或组合。

## 7. 依赖与风险

**风险**
