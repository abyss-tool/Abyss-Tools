| 规格编号 | `LIN-002` |

## 1. 目标与范围

把原虚拟机插件的 QEMU 能力收编为 Linux 插件的第二个执行域，复用同一套 `RuntimeSession`、资产通道与 Shizuku 授权。明确：QEMU 域**不是**构建器的默认路径，而是 PRoot 不可用或需要完整内核能力时的兼容域。

## 2. 组件与选型

| 组件 | 选型 | 约束 |
| --- | --- | --- |
| 引擎 | QEMU 用户态 TCG（免 KVM），arm64 原生二进制 | 无 Root、无内核模块；TCG 为慢路径，必须显著性能提示 |
| 客户机架构 | ARM64 on ARM64 优先；跨架构（x86）需二次性能确认 | N-VM-001 FR-003 |
| 机器类型 | `virt`，virtio-blk / virtio-net / virtio-gpu（无图形时用串口 + VNC） | 与镜像元数据一致 |
| 镜像格式 | qcow2（支持快照 / 差量），raw 可选 | 元数据见 DC-102 |
| 镜像来源 | Alpine（默认）/ Debian / DOS 模板；**Windows 仅用户自备，不分发** | N-VM-004 FR-002、ADR-008 |
| 显示 | VNC over 本地回环 + 随机口令；触屏 → USB Tablet / PS/2 输入路由 | 禁止 0.0.0.0 暴露 |
| 文件交换 | 9p/virtiofs 把会话工作区挂进客户机 `/workspace` | 路径 canonical 断言 |
| 网络 | 默认用户态 NAT（slirp），仅客户机主动出站；不做端口暴露给局域网 | 安全边界见 SEC-100 |
| 进程托管 | Linux 插件前台服务 + Shizuku（uid 2000）拉起，绕 `RLIMIT_MEMLOCK` / `oom_adj` | N-VM-001 / plugins.json 原 reason |
| 快照 | qcow2 内部快照 + 元数据（镜像 id / 内存大小 / 创建时间 / sha256） | DC-012 FR-004 |

## 3. 启动链路

```
openSession(QEMU_VM)
 ├─ 资产检查：imageId 分卷校验 + 整像 sha256 + 格式/大小上限（LIN-003）
 ├─ 能力探测：可用内存、memlock 上限、CPU 架构、TCG 可用性、剩余存储
 │     └─ 不满足 → 明确告知 + 降档建议，不启动注定失败的实例
 ├─ 用户确认弹层（由构建器展示，本域提供预期数据）：
 │     「完整系统域：冷启动约 1–3 分钟 / 需 X GB / 构建耗时约为 PRoot 域 3–8 倍」
 ├─ 经 Shizuku shell 上下文拉起 qemu-system-aarch64（或 App 沙箱降级）
 ├─ 挂载 9p 工作区、建立 VNC 回环、注册会话
 └─ READY（grantedFeatures 含 VNC/SNAPSHOT/PORT_FORWARD）
```

## 4. 与原 VM 插件的能力对照

| 原 `N-VM-*` | 收编后位置 | 变化 |
| --- | --- | --- |
| N-VM-001 引擎拉起与探测 | 本文件 §3 + LIN-005 | Shizuku 由 Linux 插件统一持有，不再单独授权 |
| N-VM-002 镜像管理与下载管线 | LIN-003 + DC-102 | 与 rootfs 共用 `abyss-asset-v1` 一份管线 |
| N-VM-003 VNC 显示与输入路由 | 本文件 §2 / LIN-004 | 增加回环绑定 + 随机口令 + 会话级回收 |
| N-VM-004 镜像市场模板 | DC-102 模板清单 | 模板仍版本化 JSON，Windows 不分发 |
| N-VM-005 快照 / 挂起恢复 / 性能档位 | 本文件 §5 | 档位与 `ResourceLimits` 打通 |

## 5. 性能档位与资源约束

| 档位 | vCPU | 内存 | 适用 | 约束 |
| --- | --- | --- | --- | --- |
| LOW | 1 | 512MB | 登录 / 轻量命令 | 不跑 Gradle |
| MID | 2 | 1024MB | 路径三兜底（单模块） | `org.gradle.workers.max=1` |
| HIGH | 4 | 2048MB | 多模块构建（谨慎） | 需 ≥4GB 空闲内存，否则拒绝 |

- 客户机内存 + QEMU 开销不得超过宿主可用内存的 60%；探测不足直接 `E_VM_RESOURCE`。
- 构建器请求 QEMU 域时，默认 MID；用户可在切域弹层降档。
- 快照保存前必须刷新磁盘缓存；恢复时校验快照 sha256。

## 6. 功能需求

| 编号 | 需求描述 |
| --- | --- |
| FR-001 | 启动前探测可用内存 / memlock / CPU 架构 / TCG 可用性；不满足明确告知并给降档建议，不启动。 |
| FR-002 | ARM on ARM 优先；跨架构必须显著性能提示。 |
| FR-003 | 进程生命周期由前台服务托管；退出时清理 QEMU 子进程、VNC 端口与临时文件。 |
| FR-004 | 引擎版本与能力矩阵写入 `RuntimeInfo` 供 UI 展示。 |
| FR-005 | 镜像元数据纯 JVM，分卷独立 sha256 + 整像再校验；来源 URL 过域白名单。 |
| FR-006 | 镜像删除需二次确认并同步清理快照；存储不足时预先拒绝并给出所需空间。 |
| FR-007 | 工作区经 9p/virtiofs 挂载，禁止客户机访问 App 私有目录其它部分。 |
| FR-008 | VNC 仅绑定 127.0.0.1，口令随会话随机生成、会话关闭即失效。 |
| FR-009 | 快照 / 挂起恢复可配置；恢复失败回退到最近一致快照并告知。 |
| FR-010 | Windows 客户机仅用户自备镜像，插件只提供运行时，必须展示许可合规提示。 |
| FR-011 | QEMU 域必须实现 `RuntimeSession` 公共原语子集（exec/pty/fileIn/fileOut/close）。 |

## 7. 失败语义与边界

- TCG 仿真是慢路径，禁止在 UI 中使用「高性能 / 秒级」表述。
- 镜像只做通路不做信任源（ADR-008）：镜像内容不被视为可信软件源，签名/校验只保证传输完整性。
- 客户机内取得 root **不等于宿主机 root**，文案必须区分。
- 会话不可原地换域；切域 = close 旧会话 + open 新会话，产物由构建器显式搬运。

## 8. 验收标准

| 编号 | 验收条件 |
| --- | --- |
| AC-001 | 在 arm64 设备上拉起 Alpine 镜像并通过 VNC 完成一次登录（HUB-013 AC-001）。 |
| AC-002 | 中断下载后续传不重复已完成分卷且最终 sha256 匹配（N-VM-002 AC-001）。 |
| AC-003 | QEMU 域 `exec("uname -r")` 返回客户机内核版本，与 Android 内核版本不同。 |
| AC-004 | 进程被杀 / 宿主重启后无孤儿 qemu 进程、无残留 VNC 监听。 |
| AC-005 | 非回环 VNC 绑定尝试被拒；口令在会话关闭后失效。 |
