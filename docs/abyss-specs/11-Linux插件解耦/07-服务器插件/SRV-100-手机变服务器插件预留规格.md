## 1. 这个插件要干的事（能力清单）

「手机变服务器」= 让手机上的 Linux 环境**长期对外提供服务**。按目标能力拆：

| 层级 | 能力 | 最低执行域 | 说明 |
| --- | --- | --- | --- |
| L1 | 静态 Web / 反代（Nginx、Caddy） | PRoot | 可用，但只能绑高位端口、手工管进程 |
| L1 | 脚本 / API 服务（Python、Node.js） | PRoot | 可用 |
| L1 | SSH / SFTP | PRoot | 实践端口 8022 / 2222 [citation:4][citation:6]（Haven UML Guest） |
| L2 | 数据库（SQLite/Postgres）、轻量 DNS（dnsmasq :5353） | PRoot | 可用；PRoot 顺序 I/O 约原生 60–80%，别指望高并发 [citation:20][citation:15] |
| **L3** | **容器（Podman / OCI 镜像）** | **UML 或 QEMU（真内核）** | PRoot 无 PID namespace / cgroups / overlay2 / D-Bus，**不能跑** [citation:12][citation:20][citation:13]；Podroid 用 QEMU + Alpine + Podman 可 `podman run -d -p 8080:80 nginx` [citation:11] |
| **L3** | **systemd / systemctl 服务管理** | **UML 或 QEMU** | proot-distro 官方明确「systemd is not supported and will not be supported」[citation:12] |
| **L3** | **独立网络栈 + 端口映射规则** | **UML 或 QEMU** | PRoot 共享宿主网络栈，`-p` 只能靠 userland-proxy，无法 iptables NAT [citation:20] |
| L4 | 容器镜像 / 卷 / 网络持久化 | QEMU（2–64GB 稀疏盘）或 UML（~536MB ext4） | 重启不丢 [citation:12]（Haven UML Guest） |
| L4 | VNC / 图形化管理 | QEMU | 可选 |
| L4 | 开机自拉起、崩溃重启、日志/监控 | 引擎侧常驻会话 | `LIN-007 §2` |

**结论（这条决定了架构）**：服务器插件必须能拿到**真内核域**。所以 `SRS-106 D-4` 要求在独立底座插件中新增 UML 域是硬要求，不是优化项 —— 只给 PRoot 的话，容器、systemd、真实端口映射三块全部做不了。

## 2. 插件向宿主申请什么（契约预留）

### 2.1 新增 capability（`linux-runtime-v1` 能力描述增量）

| capability | 含义 | 授予条件 |
| --- | --- | --- |
| `RESIDENT_SESSION` | 会话不随 UI 关闭回收，由引用计数 + FGS 持有 | 用户显式开启「常驻服务」；必须在通知栏可见 |
| `PORT_FORWARD` | 声明端口转发规则（`hostPort → guestPort`，TCP/UDP） | 仅 `hostPort ≥ 1024`；规则白名单校验；动态增删无需重启会话 |
| `PRIVATE_NETSTACK` | 要求独立网络栈（UML / QEMU），拒绝 PRoot 静默降级 | 域必须自带真内核 |
| `SERVICE_LIFECYCLE` | 启停 / 状态查询 / 有界重启 / 日志读取 | 每个服务一个句柄，超时与输出上限沿用 `maxExecTimeoutSec` / `maxOutputBytes` |
| `PERSISTENT_VOLUME` | 客户机持久化盘挂载 | 配额内（沿用 `defaultQuotaGb`，可收紧不可放宽） |

> 全部沿用 `DC-101` 的「能力可收紧不可放宽」纪律：宿主签发 `SessionGrant` 时把请求的 capabilities 与自身能力矩阵取交集，越权项直接拒，不做静默裁剪。

### 2.2 `SessionSpec` 增量字段（由 `LIN-007 §5` 落地）

```json
{
  "domain": "UML_GUEST",
  "resident": true,
  "restartPolicy": { "maxConsecutive": 5, "backoffBaseSec": 15, "reportAfterExhausted": true },
  "portForwards": [
    { "protocol": "tcp", "hostPort": 8080, "guestPort": 80, "bind": "127.0.0.1" }
  ],
  "services": [
    { "id": "nginx", "argv": ["/usr/sbin/nginx", "-g", "daemon off;"], "restartPolicyRef": "default" }
  ],
  "volume": { "sizeMb": 4096, "persistent": true }
}
```

`bind` 默认 `127.0.0.1`；改 `0.0.0.0`（局域网可达）必须用户二次确认并在 UI 明示风险。`hostPort < 1024` 一律 `E_PORT_PRIVILEGED`。

### 2.3 错误码增量（`DC-102` 表）

| 码 | 含义 |
| --- | --- |
| `E_PORT_PRIVILEGED` | 请求绑定 <1024 端口，非 root 应用不可绑 [citation:5][citation:15] |
| `E_PORT_IN_USE` | 宿主端口已被占用（含其它会话的规则） |
| `E_DOMAIN_NO_REAL_KERNEL` | 声明了 `PRIVATE_NETSTACK` 但只拿到 PRoot |
| `E_RESIDENT_DENIED` | 系统省电策略 / FGS 启动资格不满足，不谎报常驻成功 |
| `E_RESTART_EXHAUSTED` | 连续重启达到上限，停止重试并上报，不无限拉起 |

## 3. 平台硬约束（这些不是「难度」，是必须写进规格的物理边界）

| 约束 | 事实 | 设计应对 |
| --- | --- | --- |
| **W^X** | Android 10+ / targetSdk ≥ 29 不能 `execve()` 私有可写目录中的 ELF；可用路径只有 `system_linker_exec`（`/system/bin/linker64` 加载，Termux Play 版做法）、`targetSdk 28` 豁免、或把二进制作为 `lib*.so` 打进 APK 从只读 `nativeLibraryDir` 执行 [citation:3][citation:7][citation:9] | 引擎二进制进 APK；下载侧只放数据；`linker64` 路径下需 fork 子进程的工具（git / 包管理器 / popen）受限，整条走 Shizuku `adb_shell` 兜底 [citation:9] |
| **Phantom process killer** | Android 12+ 系统级 32 子进程上限，超额或后台高 CPU 直接 SIGKILL；Android 14+ 开发者选项可关「停用子进程限制」 [citation:3] | 首启引导一次性走完：关电池优化、加厂商睡眠白名单、提示该开关；服务进程数受控，禁止轮询式后台探测 |
| **FGS 类型与超时** | Android 14+ 必须声明 FGS 类型与权限；`dataSync` 限 6h、`shortService` 限 3min；Android 15 对部分类型引入 24h 窗口累计超时并回调 `onTimeout()`；`specialUse` 上架需 Play 审核说明 [citation:2][citation:8][citation:18] | 常驻服务按 `specialUse` 或 `connectedDevice`/`dataSync` 合规申报并写明理由；实现 `onTimeout` 优雅降级（停服务 + 通知），**不承诺 7×24 不中断** |
| **Doze / App Standby** | 未充电 + 静止 + 息屏进入 Doze，暂停后台网络、忽略普通 WakeLock；数月未主动打开会进 App Hibernation 并撤销静态广播 [citation:8][citation:10] | `PARTIAL_WAKE_LOCK` + 充电状态提示；不依赖静态广播做拉起；UI 明示「息屏/未充电时服务可能被系统暂停」 |
| **低端口** | 普通应用不能绑 <1024；实践用 8022 / 2222 / 8080 / 5353 [citation:4][citation:5]（Haven UML Guest）[citation:15] | 契约层直接拒 <1024，给出建议端口 |
| **无公网 IP** | 手机在运营商 NAT 后，外网访问必须内网穿透（frp / cloudflared），且中转需公网主机 [citation:14][citation:22] | 划为非目标（§7），插件只做到「本机 / 局域网可达」 |
| **电池与散热** | 长期满电插电会加速电池鼓包、满载机身发烫、闪存写入寿命有限 [citation:6] | 设置页给「建议充电上限 60–80% / 摘壳散热 / 重要数据异地备份」提示；不默认开启 7×24 |
| **QEMU SLIRP 边界** | 用户态 NAT 只支持出站 + 显式 `hostfwd` 入站，不支持 UPnP / STUN / 反向映射；QEMU ≥7.0 必须用 `-netdev user,...,hostfwd=tcp::8080-:80`，`-redir` 已废弃 [citation:19][citation:21] | 端口规则由引擎翻译成 `hostfwd`；`::` 绑所有接口、单冒号仅 `127.0.0.1`，默认后者 |

## 4. 生命周期与降级链（沿用 ARC-101 状态机，扩展常驻语义）

```
插件请求 openSession(SessionSpec(resident=true, domain=UML_GUEST, ...))
 ├─ 能力校验：签名 / grant / capabilities 交集 / 端口合法性
 ├─ 资源预检：剩余 RAM（UML 384MB）、持久化盘空闲（≥600MB 首次解包）、域可用
 ├─ FGS 资格检查：电池优化白名单 / FGS 类型申报 / 系统是否允许后台启动
 │     └─ 不满足 → E_RESIDENT_DENIED + 引导页（不谎报常驻）
 ├─ 拉起 UML（10–20s）或 QEMU（≤180s），客户机启动服务
 ├─ 下发端口规则 → 引擎翻译为 hostfwd / hostfs 映射
 ├─ 常驻：引用计数 ≥1、FGS 通知常显、WAKE_LOCK 持有
 ├─ 崩溃：有界重启（最多 5 次、退避递增）→ 耗尽则 E_RESTART_EXHAUSTED + 通知
 └─ 用户关闭服务 / 引用计数归零 → poweroff + 整组回收 + 撤销 grant + 释放端口
```

| 纪律 | 说明 |
| --- | --- |
| 不假装在线 | 资产 / 探测 / FGS 资格 / 端口任一未绿，`getState()` 不得返回 READY |
| 不静默换域 | 声明 `PRIVATE_NETSTACK` 却只能给 PRoot → 拒绝并说明，不悄悄降级 |
| 不无限重启 | 有界退避，耗尽即上报（避免 hold 住 wakelock 无限重连）[citation:3] |
| 会话不可原地换域 | 换域 = 停服务 + 关旧会话 + 开新会话，持久化盘显式搬运 |
| 与构建会话隔离 | 服务器常驻会话与临时构建会话分开计资源，`maxConcurrentExec` 按会话独立计（`LIN-007 §4`） |

## 5. 索引与 manifest 预留（`DC-100` / `HUB-001`）

```json
{
  "id": "abyss-plugin-phone-server",
  "version": "0.1.0",
  "minHost": 2,
  "minApp": "<主壳实际发版号>",
  "status": "planned",
  "apk": null,
  "shizuku": { "ownAuth": false, "reason": "引擎由独立底座插件 abyss-plugin-linux 唯一持有并自行授权一次；本插件经宿主 PluginBroker 中介消费，按 per-app 授权不继承原则不单独申请。" },
  "depends": [
    {
      "pluginId": "abyss-plugin-linux",
      "capability": "linux-runtime-v1",
      "versionRange": ">=0.3.0 <1.0.0",
      "optional": false,
      "requiredCapabilities": ["RESIDENT_SESSION", "PRIVATE_NETSTACK", "PORT_FORWARD", "SERVICE_LIFECYCLE", "PERSISTENT_VOLUME"]
    }
  ]
}
```

> **v1.4 修订**：`depends.pluginId` 指向**真实独立底座插件** `abyss-plugin-linux`。v1.3 曾设计 `host-builtin` 伪 id（配合 A′ 单 APK 全内置），随 `SRS-106` 采纳 B 方案而删除 —— `DependencyResolver` 走标准插件分支即可，**无需任何新增分支**，已落地代码零改动。
>
> 授权语义：`shizuku.ownAuth=false`，底座插件是全生态唯一 Shizuku 持有方；服务器插件经宿主 `PluginBroker` 拿受限会话，不单独授权。完整接入链路见 `ARC-104 §3`。
>
> `minApp` 的 `"<主壳实际发版号>"` 是**示例占位**：立项时按主壳合入 `getInternalSession()` 后的实际发版号填写（现状开发中为 `0.9.19` / code 42）。`status=planned` 期间该字段不参与 CI 版本门禁。

## 6. 安全边界（服务器对外开端口 = 攻击面，必须写死）

| 编号 | 要求 |
| --- | --- |
| FR-001 | 默认 `bind=127.0.0.1`；改 `0.0.0.0` 需用户二次确认 + 通知栏常显 + UI 明示「局域网内任何设备可访问」。 |
| FR-002 | 客户机内 root **不等于**宿主机 root；客户机只能看到自己的盘与单向 `/host` 共享目录，禁止读取手机其它数据 （Haven UML Guest）。 |
| FR-003 | 端口规则必须经白名单校验（协议 / 端口范围 / 目标域 / 归属会话），禁止任意 host path 或任意 guest 地址。 |
| FR-004 | 所有对外服务默认**不启用密码登录**、不内置默认凭据；SSH 类服务引导用户配密钥（沿用 `ADR-008`「镜像只做通路不做信任源」）。 |
| FR-005 | 插件不得申请 `INTERNET` 以外的网络特权，不得尝试改 hosts / iptables / 系统证书（非 root 本就做不到，也不做 hack）。 |
| FR-006 | 常驻服务必须在通知栏可一键停止；停止即整组回收进程、释放端口、撤销 grant。 |
| FR-007 | 日志与输出沿用 `maxOutputBytes`（1MB）上限，禁止把客户机日志直接写到宿主外部存储。 |
| FR-008 | 失败一律 fail-closed：坏清单 / 签名不符 / sha256 不符 / 越权能力 → 拒绝，目标目录零触碰。 |

## 7. 明确非目标（避免后续范围失控）

- ❌ **不提供公网服务 / 内网穿透服务端**：frp、cloudflared 等由用户自备中转主机，插件最多提供「填穿透配置」的入口 [citation:14][citation:22]。
- ❌ **不承诺 7×24 不中断**：Doze、FGS 超时、OEM 保活策略、电池与散热都是系统/物理限制，只做有界重启与如实提示 [citation:6][citation:8][citation:18]。
- ❌ **不自带 Linux 引擎**：不打包 PRoot / UML / QEMU / rootfs / 镜像，全部由独立底座插件 `abyss-plugin-linux` 经宿主中介提供。
- ❌ **不在本轮实现**：本文件只冻结挂点与契约；插件 UI、服务模板库（Nginx / Gitea / Pi-hole 一键配置等）留待立项后单独出规格 [citation:11]。
- ❌ **不分发 Windows 客户机镜像**（沿用 `N-VM-004` / `ADR-008`）。

## 8. 验收标准（预留接口的验收，不是插件功能验收）

| 编号 | 条件 |
| --- | --- |
| AC-001 | `HostCapabilityGateway` 契约测试：消费方申请 5 项 capabilities，宿主能正确取交集、越权项返回明确错误码。 |
| AC-002 | `SessionSpec(resident=true, portForwards=[{hostPort:80,...}])` 被 `E_PORT_PRIVILEGED` 拒绝；`8080` 通过。 |
| AC-003 | 声明 `PRIVATE_NETSTACK` 但宿主只给 PRoot 时返回 `E_DOMAIN_NO_REAL_KERNEL`，不静默降级。 |
| AC-004 | 常驻会话关闭后：进程组零残留、宿主端口被释放、grant 被撤销、FGS 通知消失。 |
| AC-005 | 连续杀死客户机服务 6 次，第 6 次触发 `E_RESTART_EXHAUSTED` 而非无限重启，通知栏给出可读原因。 |
| AC-006 | 索引 CI 拦截 `status=planned` / `apk=null` 条目进入可安装列表。 |
| AC-007 | 底座插件缺失或降级到无 UML 的构建、或未安装时，插件启动时得到人话提示（`E_RUNTIME_UNAVAILABLE` / `E_DOMAIN_NO_REAL_KERNEL`）而非崩溃。 |
