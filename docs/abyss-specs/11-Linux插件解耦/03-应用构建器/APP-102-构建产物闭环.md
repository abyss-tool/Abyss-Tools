## 1. 目标与范围

定义从 `fileOut(output.apk)` 到用户设备安装成功的完整链路：签名、对齐、校验、安装网关、失败诊断、切换与审计。

## 2. 闭环链路

```
会话内（Linux 插件）
  阶段 3 完成 → /workspace/build-<ts>/app-unsigned.apk
        │ fileOut(relativePath) → ParcelFileDescriptor
        ▼
构建器进程
  ① 落 App 私有缓存（临时名，canonical 断言）
  ② zipalign 对齐校验（4 字节 / 16KB 页兼容）
  ③ 签名：使用构建器独立 keystore（CI secrets 注入），v2+v3，v1 关闭（minSdk 26）
  ④ apksigner verify：签名集与指纹符合预期
  ⑤ SHA-256 计算并写入构建记录
  ⑥ 产物元信息：包名 / versionName / versionCode / 签名指纹 / 大小 / 工具链版本 / sessionId
  ⑦ PackageInstallerApkGateway：同签名门禁（覆盖安装时）+ 确认页转发 + 结果广播等待 + 超时 abandon
  ⑧ 安装结果 → UI（成功 / 用户取消 / 失败原因）
  ⑨ 关闭会话或保留供切换路径重试
```

## 3. 签名与密钥治理

| 项 | 规则 |
| --- | --- |
| 签名材料 | 仅存 GitHub Actions secrets，仓库零副本（SEC-001 FR-005） |
| 插件自身签名 | 与宿主同发布者身份，v2+v3，`apksigner` 实测门禁后才允许上传 Release（N-APP-001 FR-004） |
| 产物签名 | 构建器使用**独立**的产物签名密钥，与插件发布签名隔离；首次使用生成并提示用户备份 |
| 禁止 | 不得用发布签名签用户产物；不得把密钥写进 rootfs / 镜像 / 日志 |
| 覆盖安装 | 待装 APK 签名集必须与在装版本一致，否则拒绝（SEC-001 FR-001） |
| 密钥轮换 | 按 SEC-003 / N-SEC-003 决策登记；轮换期产物提示「签名变更需卸载旧版」 |

## 4. 校验清单（逐项 fail-closed）

| # | 校验 | 失败码 |
| --- | --- | --- |
| 1 | 文件存在且大小 > 0、非目录 | `E_ARTIFACT_EMPTY` |
| 2 | zip 魔数 / 中央目录可解析 | `E_ARTIFACT_FORMAT` |
| 3 | zipalign 对齐通过 | `E_ARTIFACT_ALIGN` |
| 4 | apksigner verify 通过 | `E_ARTIFACT_SIGN` |
| 5 | SHA-256 与构建记录一致 | `E_ARTIFACT_DIGEST` |
| 6 | 包名 / versionCode 合法 | `E_ARTIFACT_META` |
| 7 | 路径 canonical 在缓存目录内 | `E_PATH_TRAVERSAL` |
| 8 | 安装网关同签名门禁（覆盖安装时） | `E_SIGNATURE_MISMATCH` |

任一失败：保留原始产物与日志供诊断，**不删除、不静默重试、不自动换密钥**。

## 5. 安装网关行为

| 状态 | 处理 |
| --- | --- |
| 用户确认安装 | 等待系统结果广播，展示进度 |
| 用户取消 | 标记「已取消」，产物保留，可再次安装 |
| 超时 | `abandonSession()` 释放会话，提示重试（PLG-005 FR-002） |
| 同签名冲突 | 拒绝并给出人话原因 |
| 系统拦截 / 未知错误 | 展示 failureSummary + 诊断导出入口 |

## 6. 失败诊断与切换

| 失败阶段 | 诊断归类 | 是否可切路径 |
| --- | --- | --- |
| 依赖解析 | DEPS | 可（同一会话） |
| 资源编译 | RES | 可 |
| DEX / 编译 | DEX | 可（路径二 ↔ 路径三） |
| 打包 | PACK | 可 |
| 签名 / 对齐 | SIGN | 否（先修签名配置） |
| 安装 | INSTALL | 否（产物已有效，重试安装） |
| 会话不可用 / 平台限制 | RUNTIME | 否（走 LIN-004 引导 / 切域） |

- 失败界面直接提供「切换到其他方式」按钮，无需重新导入项目（原 ARCHITECTURE §3）。
- 切换不清理已有产物与底座状态，只切换执行路径。
- 记录每项目上次成功方式，下次导入作为推荐标记（不自动选中）。

## 7. 功能需求

| 编号 | 需求描述 |
| --- | --- |
| FR-001 | 产物从会话取回必须走 `fileOut` + `ParcelFileDescriptor`，不得直接读 Linux 插件私有目录。 |
| FR-002 | 签名 / 对齐 / SHA-256 三项校验全部通过才进入安装网关。 |
| FR-003 | 产物签名密钥与插件发布签名隔离，仓库零密钥副本。 |
| FR-004 | 安装结果（成功 / 取消 / 失败 / 超时）四态如实回传 UI。 |
| FR-005 | 构建记录含工具链 id/版本、sessionId、阶段耗时、产物 sha256，可导出诊断。 |
| FR-006 | 失败切换路径复用同一会话，不清理产物与日志。 |
| FR-007 | 诊断导出不得包含用户项目源码、命令正文或密钥材料（SEC-009）。 |
| FR-008 | 关闭会话前必须确认产物已落构建器私有缓存并完成校验。 |

## 8. 失败语义与边界

- 坏产物 / 签名不符 / 路径穿越一律 fail-closed 并给人话错误。
- 不得为了「能装上」而降低签名方案或跳过对齐。
- 产物安装失败不代表构建失败：UI 必须区分「构建成功但安装失败」。

## 9. 验收标准

| 编号 | 验收条件 |
| --- | --- |
| AC-001 | 三路径各产出 1 个 apksigner verify 通过且可安装的 APK。 |
| AC-002 | 构造 8 类坏产物，全部被对应错误码拒绝且原始产物保留。 |
| AC-003 | 安装超时会 abandon 会话，无残留 PackageInstaller session。 |
| AC-004 | 诊断导出经扫描不含项目源码、命令正文、密钥。 |
