## 1. 目标与范围

把原设计的三条构建路径从「自带底座」改写为「消费 RuntimeSession」，明确每条路径在不同执行域的适用性、所需资产、资源约束与失败切换语义。

## 2. 三路径总表

| 维度 | 路径一 Anpyra | 路径二 aapt2 + 固定壳 DEX | 路径三 标准 Gradle |
| --- | --- | --- | --- |
| 适用 | 单 Activity + TextView 子集的轻量项目 | 标准资源结构 / HTML·Web 内容 | 多模块 / Kotlin·Java 源码 / 依赖较多 |
| 能力边界 | 不支持 lambda、捕获局部变量、异步、任意 import、集合、多模块、发布签名 | 不编译自定义 `src/main/java|kotlin`，仅打包资源与壳 | 完整编译链路，但重 |
| 所需资产 id | `anpyra-py-<ver>` | `aapt2-arm64-<ver>`、`shell-dex-<ver>` | `jdk17-arm64`、`android-sdk-34`、`gradle-<ver>`、`aapt2-arm64` |
| 默认域 | PROOT_USERLAND | PROOT_USERLAND | PROOT_USERLAND |
| QEMU 域 | 可运行（不推荐，启动成本高） | 可运行（不推荐） | 可作 PRoot 被拦时的兜底 |
| 预估耗时 | 秒级~1 分钟 | 1–3 分钟 | 10–30 分钟（设备差异极大） |
| 内存 | 低 | 低~中 | 高（JVM 堆 ≤2048m） |
| 硬性预检 | 含 `res/`、`build.gradle`、任何 Java/Kotlin 源码 → 标注「必然不支持」 | 含自定义源码 → 提示「不编译这些源码」 | 首次选择展示资源约束说明 |

## 3. 逐路径会话编排（统一模板）

```
openSession(spec: preferredDomain=PROOT_USERLAND, requestedFeatures=[EXEC, FILE_IO])
 → fileIn(project.zip → /workspace/build-<ts>/)
 → requestAssets(toolchainIds)
 → 阶段 1 依赖解析 / 资源编译 → session.exec(argv, sink)
 → 阶段 2 DEX / 打包        → session.exec(argv, sink)
 → 阶段 3 签名 / 对齐       → session.exec(argv, sink)
 → fileOut(output.apk)
 → close() 或复用会话切换路径
```

| 纪律 | 说明 |
| --- | --- |
| argv 数组下发 | `ExecCommand` 以 argv 传递，不拼 shell 字符串（SEC-003 / LIN-005） |
| 阶段标签 | 每次 exec 带 `stage`，用于进度条与失败诊断归类 |
| 串行 | `maxConcurrentExec=1`，同一会话不并发构建 |
| 切换 | 失败切路径复用同一 sessionId，不清理产物、不重导项目 |
| 记录 | 记录每项目上次成功方式，下次作为推荐标记（不自动选中） |

## 4. 执行域适配细则

| 项目 | PROOT_USERLAND | QEMU_VM |
| --- | --- | --- |
| 域选择 | 默认；`allowDomainFallback=true` 时才考虑切换 | 仅 PRoot 探测失败 / 需完整内核能力时，用户确认后 |
| 工作区 | App 私有目录内解包的 rootfs + 绑定目录 | 9p/virtiofs 挂到客户机 `/workspace` |
| 工具链 | 由 Linux 插件在 rootfs 内安装到独立子目录 | 可复用同一工具链资产（在镜像内挂载或重新 `apk add`） |
| 网络 | 复用 Android 网络栈，Maven/pip 走白名单 | 客户机用户态 NAT，仅主动出站 |
| 路径一 | ✅ 推荐 | ⚠ 可用但冷启动不划算 |
| 路径二 | ✅ 推荐；`ldd` 验证 aapt2 依赖 | ⚠ 可用 |
| 路径三 | ✅ 默认；MID 档位以下不推荐 | ✅ 兜底；MID 档 + `workers.max=1` |
| 性能提示 | 「调试构建 1–2 分钟到数分钟甚至更长」 | 「约为 PRoot 域 3–8 倍，冷启动 1–3 分钟」 |
| 失败码 | `E_PROBE_PTRACE_BLOCKED` | `E_VM_RESOURCE` / `E_ASSET_FORMAT` |

## 5. 工具链治理（与 LIN-003 联动）

| 规则 | 内容 |
| --- | --- |
| 请求方 | 构建器只发 `requestAssets(ids[])`，不下载、不解压、不校验二进制 |
| 保管方 | Linux 插件 `:asset`，落 `assets/toolchains/<id>/<version>/` |
| 隔离 | 三路径工具链各自独立子目录，互不覆盖 |
| 验证 | aapt2 必须 ARM64 + Bionic/musl 编译版，底座内 `ldd` 全量可解析；不过不 READY |
| 版本锁 | compileSdk 暂锁 34；build-tools ≥33.0.0；NDK 用社区 ARM64 版 |
| 可复现 | 工具链 id + 版本写进构建记录（N-ENG-001），导出诊断时可见 |
| 缓存 | pip / Maven 缓存跨构建只读复用，输出目录不共享 |
| 配额 | 工具链计入 8GB 默认配额，LRU 清理不影响会话引用资产 |

## 6. 预检与三选一交互层

```
导入项目 → 静态能力预检（只分析，不拦截）
   ├─ 路径一：检测到 Python 子集 → 推荐；含 res/ → 硬性标注「必然不支持」
   ├─ 路径二：检测到标准资源结构 → 推荐；含自定义源码 → 提示不编译
   └─ 路径三：检测到多模块/Kotlin → 推荐；提示耗时与内存
 → 选择界面（推荐标记 + 风险提示 + 二次确认）
 → 用户选定 → 执行 → 产出 APK 或失败诊断
 → 失败界面直接提供「切换到其他方式」按钮
```

| 规则 | 说明 |
| --- | --- |
| 预检只提示 | 选了「看起来不匹配」的路径只弹二次确认，不拦截 |
| 例外 | 路径一对必然失败的项目特征做硬性预检标注 |
| 首次路径三 | 展示资源约束（内存上限 / 预计耗时 / 依赖下载量） |
| 进度 | 阶段进度 + 前台服务 + WakeLock 对冲后台回收 |
| 自由选择 ≠ 放任试错 | 推荐标记与风险提示必须真实来自预检结果 |

## 7. 功能需求

| 编号 | 需求描述 |
| --- | --- |
| FR-001 | 三路径实现代码不得出现执行域判断分支；域差异由会话吸收（ARC-101 FR-001）。 |
| FR-002 | 每条路径声明所需 `toolchainIds`，资产未就绪不得启动构建。 |
| FR-003 | 所有命令以 argv 下发，禁止拼接 shell 字符串。 |
| FR-004 | 失败切换路径复用同一 sessionId，保留工作区产物与日志。 |
| FR-005 | 阶段进度、退出码、stderr 摘要、耗时如实上报，不吞异常。 |
| FR-006 | aapt2 动态依赖验证不通过时，路径二与路径三不得进入 READY。 |
| FR-007 | 切域必须用户确认并展示耗时 / 存储 / 性能预期，禁止静默切域。 |
| FR-008 | 工具链版本与资产 id 写入构建记录，保证可复现。 |

## 8. 失败语义与边界

- 资源编译失败 vs 签名/对齐失败必须区分诊断（原 ARCHITECTURE §2.2）。
- 超时 / OOM 属可恢复失败：保留产物，可降档或换路径再试。
- 不得宣称 QEMU 域「高性能」；TCG 慢路径必须如实展示。
- 路径三定位「没有电脑时的可行兜底」，不是桌面替代品。

## 9. 验收标准

| 编号 | 验收条件 |
| --- | --- |
| AC-001 | 三路径在 PROOT_USERLAND 各产出 1 个可安装 APK（HUB-011 AC-002）。 |
| AC-002 | 路径三在 QEMU_VM / MID 档跑通 1 个单模块端到端用例。 |
| AC-003 | 失败切换后 sessionId 不变、工作区产物仍在、无需重导项目。 |
| AC-004 | 篡改 aapt2 为 glibc 版后，路径二/三被 `E_TOOLCHAIN_LIBC` 阻断。 |
| AC-005 | 每条 exec 的 `stage` 与进度条阶段一一对应，无跳阶段。 |
