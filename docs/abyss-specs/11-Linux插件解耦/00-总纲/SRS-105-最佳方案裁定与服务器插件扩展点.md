## 0. 裁定（先把结论钉死）

| 编号 | 裁定 |
| --- | --- |
| **D-1** | 采纳**方案 A′：单 APK 全内置**。主壳内置 PRoot + UML + QEMU 三域引擎与应用构建器编排，签名后 APK 目标 **≤ 300MB**。实测余量 285.84MB，全内置约 235MB，**不触发「>300MB 才拆插件」的兜底**。 |
| **D-2** | **保留插件机制，但用途改变**：插件不再承载引擎，只承载「消费方能力」。宿主保留 `linux-runtime-v1` 能力总线，作为后续「手机变服务器」插件的**唯一挂点**。 |
| **D-3** | **W^X 硬约束改写体积账**：Android 10+ / targetSdk ≥ 29 禁止 `execve()` 应用私有可写目录中的 ELF [citation:3][citation:7]。因此**引擎二进制必须打进 APK**（`lib*.so` 走只读 `nativeLibraryDir`，或 `system_linker_exec` / targetSdk 28 豁免）；用户「后续没事」覆盖的是 **rootfs / 镜像 / 包数据 / 工具链里的数据部分**，不含可执行引擎。这一条反过来证明「引擎按需下载」是伪方案，全内置是唯一能真正跑起来的路径。 |
| **D-4** | **必须内置 UML 真内核域**（≈13MB）：手机变服务器要跑容器 / systemd / 真 `/proc` / 独立网络栈，PRoot 无 PID namespace、无 cgroups、无 D-Bus system bus，官方明确不支持 systemd [citation:12][citation:20]。UML 补齐这一档且只多 13MB 包体。QEMU 作为容器/快照/跨架构备选，**两者都进主壳**。 |
| **D-5** | **应用构建器合入主壳**：它只是「预检 / 三路径编排 / 产物闭环」的编排逻辑，几 MB，容量允许时没有独立 APK 的理由。用户最初的「两个插件」诉求由「宿主内置引擎 + 消费方插件」这一新分工承接。 |
| **D-6** | **不推翻已落地代码，只改消费关系**：`abyss-plugin-linux` 的 7 个模块（AIDL / asset / probe / domain-proot / domain-qemu / session / shizuku）整体合入主壳 `feature:linux`；主壳已有的 `DependencyResolver` / `CapabilityBinder` / `SessionGrantIssuer` / `PluginBrokerTest` 保留，职责从「插件依赖插件」收缩为「宿主内部能力 + 对外受限会话授权」。 |
| **D-7** | 服务器插件**只做预留设计，本轮不实现**（见 `SRV-100`）；引擎侧需要的能力由 `LIN-007` 补齐。 |
| **D-8** | 全部「人日 / 工期 / 难度 / 裁剪成本」论证继续废止，不参与任何判定。 |

## 1. 为什么这个方案是「最佳」（逐条可推翻）

| 判据 | 结论 | 依据 |
| --- | --- | --- |
| 硬上限 | 235MB < 300MB，且 W^X 决定引擎只能进 APK | `SRS-104 §3` + [citation:3][citation:7] |
| 用户规则字面 | 「APK 不超 300MB 后续没事」= 上限约束；全内置不触发兜底 | 用户原话 |
| 服务器就绪度 | 内置 UML + QEMU → 真内核 / 独立网络栈 / SLIRP `hostfwd` 端口转发现成可用 | （Haven UML Guest）[citation:19][citation:21] |
| 消费方挂点 | 宿主能力总线一处，服务器插件薄 APK 即可，不装引擎、不二次授权 | `DC-101` / `ARC-102` |
| 用户安装数 | 主壳 1 个 APK 即用全部能力；要服务器才装第 2 个 | — |
| 授权次数 | Shizuku per-app 授权收敛为**主壳 1 次**（服务器插件走宿主内部会话） | `LIN-005` |
| 不浪费已写的代码 | AIDL 契约 / grant / 单测 / CI 全部复用，只搬模块与改消费关系 | `SRS-104 §2.2` |
| 后续扩展 | 再来第三个消费方插件，仍是同一套总线，不动引擎 | `SRV-100 §3` |

**与之对照、但本轮不采纳的方案**（留档，便于一句话翻转）：

| 方案 | 做法 | 未采纳原因 |
| --- | --- | --- |
| B 保留双插件（v1.0 现状） | 主壳 14MB + Linux 插件 ≈220MB + 构建器插件 + 服务器插件 | 容量上不必要；服务器与构建器改走「宿主→插件」两级；用户装 3–4 个 APK；主壳不再持有引擎，服务器常驻反而多一层进程依赖 |
| C 极简内置 | 只塞 PRoot + `aapt2/d8`（≈22MB），UML/QEMU 按需下载 | **被 D-3 否决**：W^X 下下载的引擎二进制不能执行；且服务器要真内核 |
| D 混合 | 轻量内置、重域拆插件 | A′ 已不超线，多一层拆分无收益 |

> **翻转开关**：若你实际想要的是 B（保留独立 Linux 插件作为共享底座），只需改 §4 架构图的「主壳」框为「`abyss-plugin-linux`」、把 §5 迁移表的「合入主壳」列改成「保留插件仓 + 增加服务器插件依赖」，其余规格（尤其 `SRV-100` / `LIN-007`）**完全不用改**。这是本裁定刻意保留的解耦点。

## 3. 目标架构

```
┌──────────────── 主壳 Abyss-Tools · 单个 APK ≈238MB（≤300MB）────────────────┐
│  feature:linux  （由 abyss-plugin-linux 7 模块整体合入）                     │
│   ├─ PRoot 域     Alpine 用户空间，默认，≈4MB，冷启瞬时                     │
│   ├─ UML 域       真内核 + 独立网络栈，≈13MB，384MB 运行内存（服务器默认） │
│   ├─ QEMU 域      完整 VM + SLIRP hostfwd + VNC + 快照，≈200MB            │
│   ├─ 资产通道      abyss-asset-v1：rootfs / 镜像 / 工具链数据（首启下载）   │
│   └─ 能力总线      linux-runtime-v1（原 PluginBroker / SessionGrant 演化）  │
│        │  ① 内部调用（无 Binder 跨进程）        ② 对外受限会话             │
│        ▼                                          ▼                          │
│  feature:appbuilder 预检 / 三路径 / 产物闭环      HostCapabilityGateway      │
│  feature:terminal  内置终端 / 脚本实验室            └─ 签名校验 + grant + 能力收敛 │
└───────────────────────────────────────────────────────┬─────────────────────┘
                                                        │ 消费方插件（薄 APK，几 MB）
                        ┌───────────────────────────────┴──────────────┐
                        ▼                                              ▼
        abyss-plugin-virus-guard（现状保留）        abyss-plugin-phone-server（后续）
        · 不自带引擎、不单独 Shizuku                 · 不自带引擎、不单独 Shizuku
        · 只申请受限会话                            · 申请 RESIDENT_SESSION / PORT_FORWARD
                                                     / PRIVATE_NETSTACK（见 SRV-100）
```

**三条纪律**

1. **引擎唯一持有方 = 主壳**。消费方永远拿不到 `ILinuxRuntime` 全权，只拿 `ILinuxSession` 受限代理 + 宿主签发的 `SessionGrant`（TTL ≤300s、nonce 一次性、代际翻转失效）。
2. **不静默切域**。默认 PRoot；服务器插件可声明「需要真内核」直接开 UML；UML 不可用或需 VNC/快照/跨架构才走 QEMU，切换必须弹层说明资源代价。
3. **APK 体积与首次下载量分栏展示**，运行时内存（UML 384MB、Gradle 2048m）单列性能指标，三者互不混算、互不作为形态门禁。

## 6. 验收门禁（覆盖 SRS-104 §6）

| 编号 | 条件 |
| --- | --- |
| AC-001 | 签名后 APK ≤ 300MB；`apk_size_gate` 输出逐组件体积清单（PRoot / UML / QEMU / 构建器 / 构建器工具链 ELF），累计可核对。 |
| AC-002 | 不装任何插件时，三路径构建至少路径一、路径二可产出可安装 APK；UML 域可 `apk add` 并启动一个长驻进程。 |
| AC-003 | `HostCapabilityGateway` 对消费方插件的契约测试通过：伪造签名被 `E_SIGNATURE_MISMATCH` 拒、grant 重放被 `E_GRANT_REPLAY` 拒、能力越权被拒。 |
| AC-004 | `abyss-plugin-phone-server` 占位条目通过索引 CI（`apk=null` / `status=planned` 不得进可安装列表）。 |
| AC-005 | 卸载 `abyss-plugin-virus-guard` 后主壳全部内置能力完好。 |
| AC-006 | APK 体积 / 首次下载量 / 运行时内存三者在 UI 分三栏展示，互不混算。 |
| AC-007 | W^X 验证：所有引擎 ELF 均从 `nativeLibraryDir` 或经 `linker64` 加载，私有可写目录零 `execve`。 |
