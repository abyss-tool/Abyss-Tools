## 1. 目标与范围

给出解耦后的三层进程架构、各进程职责边界、主壳与两个插件的模块地图，作为后续所有子规格的骨架。

## 2. 进程与依赖总图

```
┌──────────────────────── 进程 A：主壳 Abyss-Tools ────────────────────────┐
│ app → feature:* → core:designsystem → vendor:backdrop                     │
│ feature:* → core:{common,update,plugin,shell}                             │
│ core:plugin → core:update → core:common                                   │
│   ├─ PluginRepository / PluginInstaller / PatchEngine（既有）              │
│   └─ PluginBroker（新增）：依赖解析 / 同签名 / 能力绑定 / SessionGrant     │
│ plugin-sdk:plugin-api（HOST_API v2，纯 JVM）                              │
└───────────────┬───────────────────────────────┬─────────────────────────┘
                │ ① 索引/安装/补丁（既有链路）    │ ② AIDL 能力绑定（新增）
                │                               │  IAbyssPluginHost.getCapability
                ▼                               ▼
┌──────────── 进程 B：abyss-plugin-linux ────────────┐  ┌── 进程 C：app-builder ──┐
│ LinuxRuntimeService（exported，前台服务托管）        │◄─┤ 依赖 depends（不直连）    │
│  ├─ AssetManager      abyss-asset-v1 下载/校验/配额 │  │ 预检 / 三路径 / 产物闭环  │
│  ├─ DomainProbe       ptrace / memlock / 架构探测   │  │ 无 rootfs / 无 PRoot      │
│  ├─ SessionManager    引用计数 / 状态机 / 死亡回收   │  │ 无 QEMU / 无 Shizuku      │
│  ├─ Domain:PROOT      proot-distro-nolib + Alpine  │  │                            │
│  ├─ Domain:QEMU       TCG + qcow2 + VNC + 快照      │  │                            │
│  ├─ ShizukuExecutor   uid 2000 唯一授权入口          │  │                            │
│  └─ WorkspaceProvider 会话内文件进出（受限）         │  │                            │
└────────────────────────────────────────────────────┘  └──────────────────────────┘
                ▲
                │ Shizuku（唯一一次 per-app 授权）
                ▼
        ADB shell 上下文（uid 2000）/ 或 App 沙箱纯 PRoot 降级
```

关键单向性：**构建器 → 宿主 → Linux 插件**。构建器永不直接持有 Linux 插件的 Binder 全权，也不持有 Shizuku 句柄。

## 3. 主壳模块地图（增量部分）

| 模块 | 形态 | 新增/修改 | 职责 | 必须保持 |
| --- | --- | --- | --- | --- |
| `plugin-sdk:plugin-api` | 纯 JVM | 修改 | `HOST_API_VERSION=2`、`PluginManifest` 增 4 字段、`DependsSpec` / `ProvidesSpec` / `CapabilitySpec` 数据类 | 零 Android 依赖、`ignoreUnknownKeys=true` |
| `core:plugin` | 纯 JVM | 修改 | 新增 `PluginBroker`、`DependencyResolver`、`CapabilityBinder`、`SessionGrantIssuer` | 纯 JVM 可单测 |
| `core:common` | 纯 JVM | 修改 | 新增 `CapabilityId` / `RuntimeDomain` / `SessionState` 枚举常量、`SemVer` 区间比较 | 单一事实源 |
| `core:shell` | Android 库 | 修改 | `ShizukuCommands` 增 Linux 会话启动模板（只读探测 / 进程拉起） | 指令编排零 Android 依赖，集中维护 |
| `feature:plugins` | UI | 修改 | 插件详情页展示「依赖 / 被依赖 / 能力 / 授权归属」卡片、安装序引导 | 业务 UI 走 designsystem/glass |
| `core:common/ToolCatalog` | 纯 JVM | 修改 | 新增 PLUGIN 条目 `abyss-plugin-linux` | id 唯一且 PLUGIN 的 pluginId 非空 |
| `app` | Android | 修改 | Broker 的 Android 侧注入（PackageManager 查询 / Binder / DeathRecipient） | 手动 DI，不引 Hilt |

> 依赖方向校验：新增的 `core:plugin` 仍只依赖 `core:update`、`core:common`、`plugin-sdk:plugin-api`；不得反向依赖 `app` 或 `feature:*`（ARC-001 AC-001）。

## 4. Linux 插件模块地图（新建仓）

| 模块 | 形态 | 职责 | 对应规格 |
| --- | --- | --- | --- |
| `:app` | Android | 插件入口、前台服务、`LinuxRuntimeService`、权限声明 | LIN-004 |
| `:runtime-api` | 纯 JVM + AIDL | `ILinuxRuntime` / `ILinuxSession` / 数据类，供宿主与构建器 compileOnly | DC-101 |
| `:asset` | 纯 JVM + Android 下载实现 | `abyss-asset-v1` 清单解析、分卷校验、断点续传、配额 | LIN-003 / DC-102 |
| `:probe` | 纯 JVM + JNI 探测 | ptrace / memlock / arch / 存储探测与降级决策 | LIN-005 |
| `:domain-proot` | Android 库 + 原生库 | proot-distro-nolib 嵌入、Alpine rootfs 解包、chroot 模拟 | LIN-001 |
| `:domain-qemu` | Android 库 + 原生库 | QEMU TCG 拉起、镜像挂载、VNC、快照、9p/virtiofs 共享 | LIN-002 |
| `:session` | 纯 JVM | `RuntimeSession` 状态机、引用计数、限额、工作区路径断言 | ARC-101 / LIN-004 |
| `:shizuku` | Android 库 | 唯一授权检测与 shell 上下文执行（Shizuku AAR 只进此模块） | LIN-005 |
| `:tools` | Python 脚本 | 复刻 `validate_plugin.py` / `make_patch.py` / `publish_patch.py` + 新增 `validate_assets.py` | ENG-100 |

模块纪律沿用 ARC-002：每个 include 必须有 `build.gradle.kts` 与至少一个源文件，禁止空模块；`repositoriesMode = FAIL_ON_PROJECT_REPOS`；JDK 17 配置期人话报错。

## 6. 功能需求

| 编号 | 需求描述 |
| --- | --- |
| FR-001 | 三个 APK 的进程边界清晰：主壳不执行 Linux 命令，构建器不持有引擎，Linux 插件不做 APK 构建编排。 |
| FR-002 | 主壳所有新增纯 JVM 模块单测零 Android 依赖，可 `./gradlew test` 独立跑通。 |
| FR-003 | Linux 插件的 AIDL 接口定义在 `:runtime-api`，宿主与构建器以 compileOnly 依赖，禁止拷贝接口源文件。 |
| FR-004 | 模块图无环；`settings.gradle.kts` include 行数与模块数一致（ARC-002 AC-001）。 |
| FR-005 | 新增 feature 条目同步 `ToolCatalog` 与 `AbyssRoot` 路由。 |
| FR-006 | 所有跨进程数据类可 Parcelable / Serializable，字段变更必须走能力版本升级。 |
| FR-007 | 插件崩溃不得导致宿主重启，宿主崩溃不得遗留孤儿 PRoot/QEMU 进程（N-PLG-002 FR-005 / LIN-004）。 |

## 7. 失败语义与边界

- 任一模块初始化失败 → `UiState.Error` + 人话原因，禁止静默降级。
- 资产缺失时 Linux 插件可运行「未初始化」状态但不得假装 READY；构建器收到 `UNAVAILABLE` 必须阻断构建。
- 路径断言：工作区 canonical 路径必须位于 App 私有目录内，穿越即拒（PLG-005 FR-005）。

## 8. 验收标准

| 编号 | 验收条件 |
| --- | --- |
| AC-001 | 依赖图静态分析无环，且无 `feature → feature` 边。 |
| AC-002 | 三仓 `./gradlew test` 中纯 JVM 模块在 JVM（非 Robolectric）环境下全绿。 |
| AC-003 | 卸载 Linux 插件后，构建器启动不崩溃并给出引导；重新安装后无需重启主壳即可恢复。 |
