## 2. 改造后 plugin.json（目标形态）

```json
{
  "id": "abyss-plugin-app-builder",
  "name": "应用构建器",
  "version": "0.2.0",
  "minHost": 2,
  "minApp": "0.10.0",
  "category": "dev",
  "summary": "手机端 APK 构建：静态预检 + Anpyra / aapt2 固定壳 / 标准 Gradle 三路径，依赖 Linux 插件提供的运行环境。",
  "icon": "🏗",
  "permissions": ["FOREGROUND_SERVICE", "WAKE_LOCK", "REQUEST_INSTALL_PACKAGES", "INTERNET"],
  "depends": [
    {
      "pluginId": "abyss-plugin-linux",
      "capability": "linux-runtime-v1",
      "versionRange": ">=0.2.0 <1.0.0",
      "optional": false,
      "reason": "构建需要 Linux 运行环境（PRoot 用户态 / QEMU 完整系统），由 Linux 插件统一提供并持有 Shizuku 授权。"
    }
  ],
  "entry": "com.abyss.plugin.appbuilder.AppBuilderPlugin",
  "repo": "abyss-tool/abyss-plugin-app-builder",
  "patchChannel": "https://raw.githubusercontent.com/abyss-tool/abyss-plugin-app-builder/main/patches/index.json",
  "roadmap": ["v0.2 依赖握手与会话编排", "v0.3 路径一", "v0.4 路径二", "v0.5 路径三", "v0.6 三选一交互层"]
}
```

**字段变化对照**

| 字段 | v0.1.0（现状） | v0.2.0（目标） | 原因 |
| --- | --- | --- | --- |
| `minHost` | 1 | 2 | 依赖解析与能力绑定是 HOST_API v2 职责 |
| `minApp` | 0.2.0 | 0.10.0 | 需含 PluginBroker 的宿主版本（按实际发版号定稿） |
| `shizuku` | `ownAuth=true` + reason | **删除** | 底座已移出，不再需要 shell 上下文 |
| `depends` | 无 | 1 条非可选依赖 | 显式声明能力、插件 id、版本区间 |
| `permissions` | 3 项 | 增 `INTERNET` | 仅用于构建依赖解析请求（由 Linux 插件资产通道统一执行大下载） |
| `version` | 0.1.0 | 0.2.0 | 语义化升版；CHANGELOG 与 patches.latest 同步 |
| `summary` | 含「Alpine + PRoot 底座」 | 改为「依赖 Linux 插件」 | 文案与职责一致 |

## 3. CI 门禁变更（validate_plugin.py）

| 原校验 | 目标校验 |
| --- | --- |
| shizuku 声明**必填**且 ownAuth=true、reason ≥10 字符 | **显式断言不得出现 `shizuku`**；出现即失败并提示「底座已迁至 Linux 插件」 |
| 三处一致性（version / CHANGELOG / patches.latest） | 保留 |
| repo 末段 == id、归属 abyss-tool | 保留 |
| 无 depends 校验 | 新增：`depends[].pluginId` kebab-case、 capability == `linux-runtime-v1`、`versionRange` 可被 SemVer 解析、`optional=false` 时 `reason` 非空 |
| — | 新增：`minHost >= 2` 且 `minHost <= 当前 HOST_API` |
| — | 新增：静态扫描 `src/` 不含 `proot` / `rootfs` / `qemu` / `Shizuku` / `ILinuxRuntime` 引用 |

`plugin-ci.yml` 在 M2 增加：Gradle assemble + 单元测试 + 上述静态扫描；APK 上传 Release 供 `sync_index.py` 自动填 `apk`（N-APP-001 FR-005/006）。

## 4. 安装序（宿主侧）

```
用户在插件中心点「安装 应用构建器」
 → PluginBroker.resolve() → installOrder = [abyss-plugin-linux, abyss-plugin-app-builder]
 → 若 Linux 插件未安装：展示依赖清单 + 「一并安装」按钮（用户确认）
 → 依次：下载 → SHA-256 → 同签名门禁 → PackageInstaller 确认页 → 结果广播 → 版本账本
 → 安装成功后写依赖账本（供卸载级联提示）
 → 不自动启动构建，引导用户完成 Shizuku 授权与资产下载
```

| 场景 | 引导文案（人话） | 动作 |
| --- | --- | --- |
| Linux 插件缺失 | 「应用构建器需要 Linux 插件提供运行环境，请先安装」 | 一键跳转 / 一并安装 |
| Linux 插件版本过低 | 「Linux 插件需升级到 0.2.0 以上」 | 跳转补丁 / Release |
| Linux 插件已装但未授权 | 「请在 Shizuku 里为 Linux 插件授权一次」 | 跳转授权引导 |
| 资产未就绪 | 「运行环境组件尚未下载完成」 | 跳转 Linux 插件资产页 |
| 宿主版本过低 | 「请升级深渊工具到 0.10.0 以上」 | 跳转主壳更新 |

## 5. 启动握手（逐帧）

| 步 | 调用 | 成功 | 失败 |
| --- | --- | --- | --- |
| 1 | 读自身 manifest | minHost=2 / depends 合法 | 本地 manifest 坏 → Error 页 |
| 2 | `IAbyssPluginHost.getCapability("linux-runtime-v1")` | 受限 `ILinuxSession` 代理 | `E_DEP_MISSING` / `E_SIGNATURE_MISMATCH` / `E_GRANT_INVALID` |
| 3 | `getRuntimeInfo()` | 版本 / 域 / 资产 / 授权 / 探测摘要 | `E_RUNTIME_UNAVAILABLE` |
| 4 | 依 `RuntimeInfo` 分流 | 全绿 → 项目导入 | 四类引导（见 §4） |
| 5 | `openSession(spec, grant)` | sessionId + 句柄 | `E_ASSET_*` / `E_PROBE_*` / `UNAVAILABLE` |
| 6 | `requestAssets(toolchainIds)` | assetsReady | 展示下载进度，不启动构建 |
| 7 | 构建 | 阶段进度 | 失败切换路径复用同一会话 |

## 6. 功能需求

| 编号 | 需求描述 |
| --- | --- |
| FR-001 | `depends` 为非空数组且 `optional=false`；能力 id 固定 `linux-runtime-v1`。 |
| FR-002 | 构建器不得缓存 `SessionGrant`；每次 openSession 重新向宿主申请。 |
| FR-003 | 安装 / 启用 / 启动三处都做依赖解析，任一不满足 fail-closed。 |
| FR-004 | 卸载 Linux 插件时宿主必须提示「应用构建器将不可用」并给出级联处置。 |
| FR-005 | 握手阶段所有远端/跨进程状态走 `UiState` 三态，加载中禁止假数据。 |
| FR-006 | 构建器版本升级不得强制 Linux 插件同步升级，除非能力主版本变化。 |
| FR-007 | 引导文案不得暴露错误码原文；错误码进日志与诊断导出。 |
| FR-008 | `minApp` 与宿主实际发版号一致性由 Hub CI 校验。 |

## 7. 失败语义与边界

- 依赖缺失 / 低版本 / 签名不符 / 授权缺失统一 fail-closed，不降级为「凑合跑」。
- 不得在 Linux 插件不可用时回退到宿主 shell 或内置终端执行构建。
- 资产下载中展示真实进度，禁止显示假 READY。

## 8. 验收标准

| 编号 | 验收条件 |
| --- | --- |
| AC-001 | `validate_plugin.py` 对目标 plugin.json 全绿；注入 `shizuku` 字段后立即失败。 |
| AC-002 | 四种失败状态（缺失 / 低版本 / 未授权 / 资产未就绪）各有正确引导与截图留痕。 |
| AC-003 | 一键「一并安装」按拓扑序完成两个 APK 安装，账本记录依赖。 |
| AC-004 | v1 宿主加载本插件被拒并提示升级；v2 宿主正常。 |
