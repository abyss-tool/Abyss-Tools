| 规格编号 | `SEC-100` |

## 1. 目标与范围

把解耦后新增的「插件 ↔ 宿主 ↔ 插件」信任面逐条收紧，明确什么能做什么不能做，以及许可合规边界。

## 2. 四层信任链

| 层 | 校验 | 失败动作 |
| --- | --- | --- |
| L1 发布签名 | 插件 APK 签名集与在装版本一致；发布者指纹命中 `PublisherSignatures.PINNED_SHA256` | `E_SIGNATURE_MISMATCH`，拒绝安装/绑定 |
| L2 CI 门禁 | `apksigner verify` 实测指纹一致才允许上传 Release；签名材料仅存 GitHub Actions secrets，仓库零副本 | 发布动作失败 |
| L3 渠道白名单 | `ChannelPolicy`：repo 正则、patchChannel 正则、资产 URL 域白名单、重定向后复检 host、sha256 64 位 hex | `E_ASSET_URL_DENIED`，整页 Error |
| L4 运行时令牌 | `SessionGrant` 五元组（包名 / 签名指纹 / capability / sessionId / nonce）+ TTL + 宿主签名 | `E_GRANT_*`，拒绝 bind |

**新增约束**：Linux 插件的 `LinuxRuntimeService` 虽 exported，但 `onBind` 无 grant 直接返回 null；消费方禁止持有 `ILinuxRuntime`，只拿 `ILinuxSession` 受限代理。

## 3. 跨插件鉴权矩阵

| 调用方 | 允许 | 禁止 |
| --- | --- | --- |
| 宿主 `PluginBroker` | 绑定 `ILinuxRuntime`、签发/撤销 grant、查询 `RuntimeInfo` | 执行用户项目命令、读取项目内容 |
| 应用构建器 | `getCapability` → `ILinuxSession` 的 exec/pty/fileIn/fileOut/close | 直连 service、拿 Shizuku Binder、读 Linux 插件私有目录、提高限额 |
| Linux 插件 | 校验 grant、执行 argv、管理资产与会话 | 反向调用构建器私有接口、把 rootfs 路径暴露给消费方 |
| 任意第三方 APK | 无 | 任何 bind / exec（同签名 + 白名单包名 + depends 三重不匹配） |
| 主壳内置终端 / 脚本实验室 | 未来可经宿主申请会话（需新增 depends 声明） | 本期不开放 |

## 4. 注入与路径防护

| 面 | 措施 | 依据 |
| --- | --- | --- |
| shell 注入 | 模板集中 `LinuxCommands.kt`；`requireSafeToken` 白名单 `[A-Za-z0-9._:-]`；自由文本 `shellQuote`；业务模块禁止拼 shell | SEC-003 / SHL-002 |
| 命令注入 | `ExecCommand` 以 argv 数组下发，服务端拒绝单字符串命令 | DC-101 FR-003 |
| 路径穿越 | 工作区 canonical 断言在 App 私有目录内；`../`、绝对路径、软链逃逸一律拒 | PLG-005 FR-005 / DC-007 FR-002 |
| 补丁包 | zip 三重防护：路径不含 `../`、载荷与 manifest 一一对应、写失败整体回滚 | SEC-004 |
| 资产包 | 分卷 + 整像双层 sha256、格式魔数、大小上限、原子 rename | LIN-003 |
| Binder | DeathRecipient + 超时 + 死亡撤销 grant；插件崩溃不带崩宿主 | N-PLG-002 FR-004/005 |
| VNC | 仅 127.0.0.1 + 随机会话口令 + 关闭即失效 | LIN-002 FR-008 |

## 5. 权限与数据最小化

| 项 | 规则 |
| --- | --- |
| Linux 插件权限 | `INTERNET`（资产/依赖下载）、`FOREGROUND_SERVICE`、`WAKE_LOCK`；不申请 `REQUEST_INSTALL_PACKAGES` |
| 构建器权限 | `FOREGROUND_SERVICE`、`WAKE_LOCK`、`REQUEST_INSTALL_PACKAGES`、`INTERNET`；无 Shizuku 相关权限 |
| 审计日志 | 只记 sessionId / capability / 错误码 / 阶段 / 耗时；不记命令正文、项目源码、密钥、镜像内容 |
| 诊断导出 | 不含用户项目源码、命令正文、密钥、VNC 口令；导出前做敏感串扫描 |
| 远端数据 | 统一 `UiState` 三态；加载中禁止假数据 |
| 隐私 | 不上传设备指纹、已装应用列表、项目内容；镜像/包管理源不被视为可信来源（ADR-008） |

## 6. 合规边界

| 项 | 结论 |
| --- | --- |
| Shizuku | uid 2000 shell 级，**不是 root**；不能 `su`、不能任意突破 SELinux；不得暗示绕过厂商安全策略 |
| 平台限制 | ColorOS / MagicOS 的 ptrace 限制属平台限制，不得包装成代码缺陷或提供「绕过」承诺 |
| 客户机 root | QEMU 域客户机内 root ≠ 宿主机 root，文案必须区分 |
| 许可 | 沿用 UGRL v1.0；Alpine / Debian / QEMU / PRoot 各自许可随资产 `license` 字段列明 |
| Windows 镜像 | 不分发；仅用户自备，插件只提供运行时并展示许可合规提示（N-VM-004 FR-002） |
| 签名密钥 | 插件发布签名与用户产物签名隔离；仓库零密钥副本 |
| targetSdk | 主壳钉 28 决策不变；执行域迁移先于任何升级验证（SEC-007 / N-CMP-001） |

## 7. 功能需求

| 编号 | 需求描述 |
| --- | --- |
| FR-001 | 任一 L1–L4 校验失败一律 fail-closed 并给人话错误，不抛异常穿透 UI。 |
| FR-002 | `getCapability` 四重校验（包名白名单 / 签名 / depends 匹配 / minHost）缺一不可。 |
| FR-003 | grant TTL ≤300s，可撤销，不可跨会话复用、不可持久化。 |
| FR-004 | 无中介直连尝试记 `E_DIRECT_BIND_DENIED` 并写审计。 |
| FR-005 | 所有资产下载过域白名单 + 重定向复检 + sha256。 |
| FR-006 | 审计与诊断导出经敏感串扫描，命中即阻断导出。 |
| FR-007 | 高危动作（切域 / 删除镜像 / 卸载依赖插件 / 覆盖安装）必须二次确认并留审计（SEC-010）。 |
| FR-008 | 文档/UI 不得出现「root」「刷内核」「绕过安全策略」等误导表述。 |

## 8. 验收标准

| 编号 | 验收条件 |
| --- | --- |
| AC-001 | 未签名第三方 APK 冒充构建器调用能力，被拒且宿主无状态变化。 |
| AC-002 | grant 过期 / 重放 / 跨会话复用三类用例全部拒绝。 |
| AC-003 | 注入用例集（shell 元字符、单字符串命令、路径穿越、软链）全部被拒且目标零触碰。 |
| AC-004 | 非回环 VNC 绑定被拒；诊断导出不含项目内容。 |
| AC-005 | 三层信任链 CI 门禁（签名 / 指纹 / apksigner）全部可复现。 |
