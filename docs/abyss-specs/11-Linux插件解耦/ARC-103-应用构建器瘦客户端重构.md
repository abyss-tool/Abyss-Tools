## 1. 目标与范围

逐项列出构建器的保留、删除、迁移、新增职责，并给出改造前后对照与回归风险。本文件只定边界，三路径细节见 APP-101，产物闭环见 APP-102。

## 2. 改造前后对照

| 维度 | 改造前（现骨架设计） | 改造后 |
| --- | --- | --- |
| 进程内底座 | Alpine rootfs + PRoot（约 4MB，打包进 APK） | 无；通过 `ILinuxSession` 使用 Linux 插件的会话 |
| Shizuku | `shizuku.ownAuth=true`，用户为构建器单独授权 | 删除声明；由 Linux 插件统一授权一次 |
| 引擎资产 | PRoot AAR / ARM64 工具链 / JDK+Gradle 均在构建器私有目录 | 引擎与 rootfs 在 Linux 插件；工具链作为 `abyss-asset-v1` 资产由构建器**请求**、Linux 插件**保管** |
| QEMU / 镜像 / VNC | 无（在另一个插件仓） | 由 Linux 插件 `QEMU_VM` 域提供，构建器可请求切域 |
| 能力探测 | 自己跑 ptrace 探测与降级链 | 读 `RuntimeInfo.probeSummary`，不自己探测 |
| 执行 | 自己拼 `Shizuku → PRoot → Alpine` 链 | `session.exec(...)`，不感知域与 uid |
| 工作区 | `/workspace/build-<ts>` 自建 | 由会话分配，构建器只拿到相对路径 |
| 前台服务 | 长时间构建保活 | 保留（构建器侧进度 / WakeLock），不再托管引擎进程 |
| 职责 | 底座 + 预检 + 三路径 + 产物闭环 | 预检 + 三路径 + 产物闭环 + 会话编排 |
| 依赖声明 | 无 | `depends: abyss-plugin-linux >= 0.2.0, linux-runtime-v1` |
| minHost | 1 | 2 |

## 5. 新增职责

| 编号 | 职责 | 验收要点 |
| --- | --- | --- |
| N-1 | 启动时依赖握手：查询宿主 → 获取能力代理 → 读 `RuntimeInfo` → 决定可用/引导 | 缺失/低版本/未授权/未就绪四种引导 |
| N-2 | `SessionGrant` 消费与续期 | 过期自动重新 `getCapability`，不缓存 grant |
| N-3 | 会话生命周期管理：一个构建 = 一次 `openSession`，失败切换路径复用同一会话 | 切换路径不重建会话、不清产物 |
| N-4 | 工具链资产请求：`requestAssets(ids[])` → 等待 `assetsReady` → 再开始构建 | 资产未就绪时不启动注定失败的构建 |
| N-5 | 域切换确认：仅当用户勾选 `allowDomainFallback` 且弹层确认后才允许 QEMU | 展示启动耗时与存储占用 |
| N-6 | DeathRecipient / 会话 CLOSED 的 UI 恢复 | 不崩溃、可重试、保留项目 |
| N-7 | 审计字段 `clientTag` 与 sessionId 关联构建日志 | 日志可追溯但不落命令正文 |

## 6. 启动握手流程

```
构建器启动
 ├─ 读自身 plugin.json（minHost=2 / depends）
 ├─ 宿主 PluginBroker.resolve() → 不通过 → 引导页（安装/升级/授权）
 ├─ getCapability("linux-runtime-v1") → 受限代理
 ├─ getRuntimeInfo()
 │    ├─ assetsReady=false → 展示资产下载入口（由 Linux 插件执行）
 │    ├─ shizukuState≠GRANTED → 引导用户去 Shizuku 授权 Linux 插件
 │    ├─ probeSummary=PROOT_BLOCKED → 展示切域选项
 │    └─ 全绿 → 进入项目导入
 └─ 导入项目 → 预检 → 三选一 → openSession → requestAssets → 构建
```

## 7. 功能需求

| 编号 | 需求描述 |
| --- | --- |
| FR-001 | 构建器 `plugin.json` 不得含 `shizuku` 字段；CI 门禁改为「若出现 shizuku 即失败」。 |
| FR-002 | 构建器不得声明 `FOREGROUND_SERVICE` 之外的引擎类权限；`REQUEST_INSTALL_PACKAGES` 保留用于产物安装。 |
| FR-003 | 构建器不得直接读写 Linux 插件私有目录，文件进出必须走 `fileIn/fileOut`。 |
| FR-004 | 三条路径的实现代码中不得出现执行域判断分支；域差异由会话抽象吸收。 |
| FR-005 | 失败切换路径必须复用同一 sessionId，工作区产物保留。 |
| FR-006 | 工具链版本与资产 id 写进构建记录，保证可复现（N-ENG-001 本地可复现构建环境）。 |
| FR-007 | 构建器版本升级不得要求 Linux 插件同步升级，除非 `capability` 主版本变化。 |
| FR-008 | 全部新增交互文案使用人话，禁止暴露错误码原文（错误码仅进日志与诊断导出）。 |

## 8. 失败语义与边界

- Linux 插件不可用 → 构建器只能展示引导，不能「降级」为自带底座或调用宿主 shell 凑合。
- 会话中途 CLOSED → 当前构建标记失败，保留产物与日志，可重试。
- 路径三首次选择必须展示资源约束（内存上限 / 预计耗时 / 依赖下载量）。
- 不得因「用户选了看起来不匹配的路径」而拦截，只做二次确认（原设计核心原则）。

## 9. 验收标准

| 编号 | 验收条件 |
| --- | --- |
| AC-001 | 静态扫描构建器仓：无底座实现文件、无 `shizuku` 声明、无 `ILinuxRuntime` 引用。 |
| AC-002 | 在 Linux 插件未安装 / 未授权 / 资产缺失 / 探测失败四种状态下，构建器分别给出正确引导。 |
| AC-003 | 三路径在 PRoot 域各产出 1 个可安装 APK；路径切换复用同一 sessionId。 |
| AC-004 | 卸载 Linux 插件后构建器启动不崩溃；重装后无需重启宿主即可恢复。 |
