## 1. 目标与范围

在不破坏「小功能内置、大引擎插件化」三分法的前提下，重划仓库职责：新增 Linux 引擎插件仓，收编虚拟机骨架，明确每个仓的单一事实源与数据流向。

## 2. 承载形态判定（对照 ADR-001）

| 能力 | 判定 | 理由 |
| --- | --- | --- |
| Linux 运行环境（PRoot + Alpine + QEMU + 镜像 + 会话） | **PLUGIN（新建 `abyss-plugin-linux`）** | 自带完整引擎、数 MB~数 GB 资产、独立进程与独立授权，典型引擎级插件 |
| 应用构建器（预检 / 三路径 / 产物闭环） | **PLUGIN（保留，瘦化）** | 仍是重能力，但自身不再持有引擎；依赖 Linux 插件 |
| 病毒拦截 | PLUGIN（不变） | 与本方案无耦合 |
| 原虚拟机插件 | **归档（收编为 QEMU 执行域）** | 避免两套镜像管线 / 两套 Shizuku 授权 / 两套前台服务 |
| 内置终端 / 脚本实验室 / 工具目录 / 插件中心 / 更新引擎 | BUILT_IN（不变） | v0.8.0 大内置化成果，不回退 |
| 宿主插件框架新增 `PluginBroker` | BUILT_IN（主壳内） | 依赖解析属框架职责，不能放进插件 |

> 纪律：`SRS-004` FR-005「归档能力不得再以插件形式复活」。QEMU 能力**不是复活虚拟机插件**，而是以新插件的一个执行域承接，仓库 id、包名、签名身份均为 `abyss-plugin-linux`。

## 4. 数据流向

```
Abyss-Plugins/plugins.json (hubVersion 0.4.0)
   │  含 depends / provides / capabilities / apk / patchChannel / assetChannel
   ▼
主壳 PluginRepository → PluginBroker（依赖解析 / 同签名 / 令牌）
   │  安装序：abyss-plugin-linux → abyss-plugin-app-builder
   ▼
abyss-plugin-linux（唯一持有）
   ├─ assets/index.json (abyss-asset-v1) → rootfs / VM 镜像 / 引擎原生库
   ├─ patches/index.json (abyss-plugin-patches-v1，仅小数据)
   └─ RuntimeSession(PROOT_USERLAND | QEMU_VM) ← Shizuku 唯一授权
   ▲
   │  ILinuxSession 受限代理（经宿主签发 SessionGrant）
abyss-plugin-app-builder（无底座、无 Shizuku）
   └─ 三路径编排 → 产物 APK → 签名校验 → 安装网关
```

## 5. 功能需求

| 编号 | 需求描述 |
| --- | --- |
| FR-001 | 新仓 id 必须 kebab-case 且等于仓库名 `abyss-plugin-linux`，符合 `ID_PATTERN`。 |
| FR-002 | 新仓骨架完全复用 `ADDING_PLUGINS.md` 7 步流程（plugin.json / CHANGELOG / ROADMAP / patches/index.json / tools 三脚本 / 两个 workflow / LICENSE）。 |
| FR-003 | `sync_index.py` 的 `REPOS` 注册表同步增删；单仓故障保留旧条目并告警，不阻塞生态滚动。 |
| FR-004 | `plugins.json` 不得包含任何归档 id；VM 归档后条目必须移除，客户端展示归档说明而非隐藏。 |
| FR-005 | 主壳 `ToolCatalog` 新增 PLUGIN 条目 `pluginId=abyss-plugin-linux`，`status=PLUGIN` 且 `pluginId` 能命中索引。 |
| FR-006 | 索引条目 `apk=null` 期间必须展示「资产未发布」（沿用 HUB-001 FR-004），不得隐藏条目。 |
| FR-007 | 归档仓禁止再发补丁；归档公告需指明能力去向：`QEMU_VM 执行域 → abyss-plugin-linux`。 |
| FR-008 | 主壳版本号仍只在 `AppInfo.kt`；插件版本只在本仓 `plugin.json`，禁止跨仓复制字面量。 |
| FR-009 | 发布仓不存源码、开发仓不存签名材料，双仓纪律不变。 |
| FR-010 | 所有新增 / 变更字段必须同时更新测试夹具镜像（`src/test/resources`）与 Hub CI 校验。 |

## 6. 失败语义与边界

- `plugins.json` 中出现归档 id、重复 id、依赖指向不存在 id → 整页 Error，不展示部分数据（PLG-003 FR-001/002）。
- 单仓 CI 红灯不得合并；Hub CI 红灯不得滚动索引。
- 归档仓历史 manifest 中的旧组织字段仍按历史漂移登记，不得被运行时索引采纳（HUB-014 FR-002）。
