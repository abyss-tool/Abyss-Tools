## 1. 为什么要单独出这份

现有 `LIN-004` 的会话模型是**临时型**：`openSession → exec/pty → close`，引用计数归零即整组回收，`maxConcurrentExec=1`。服务器场景要的是**常驻型**：服务不随 UI 关闭、崩溃要有界重启、端口要能从宿主映射到客户机、资源不能和临时构建互相挤死 [citation:3][citation:8]。

两者共用同一套 `RuntimeSession`，靠 `SessionSpec.resident` 分叉，**不新增第二套会话引擎**。

## 2. 常驻会话（`RESIDENT_SESSION`）

### 2.1 生命周期扩展

| 阶段 | 临时会话（现状） | 常驻会话（本规格新增） |
| --- | --- | --- |
| 持有 | UI 引用计数 | 引用计数 + **FGS 前台服务句柄** + `PARTIAL_WAKE_LOCK` |
| 可见性 | 无通知或普通进度通知 | **通知栏常显**，含服务名、域、端口、内存占用、一键停止 |
| 关闭触发 | 用户关页面 / close() | 用户点「停止服务」/ 引用计数归零 / 系统 `onTimeout` / 授权撤销 |
| 崩溃 | 报错 + 会话进入 FAILED | **有界重启**：最多 5 次连续、退避递增（15s 起），耗尽报 `E_RESTART_EXHAUSTED` 并停止重试 [citation:3] |
| 回收 | 进程组 kill | `poweroff` + 整组回收 + 释放端口 + 撤销 grant + 释放 FGS/WakeLock |
| 状态上报 | `getState()` | 增加 `resident` / `uptimeSec` / `restartCount` / `boundPorts` / `fgsType` |

> 纪律：**不无限重启**。无界重试会 hold 住 wakelock、让 UI 永远停在「重连中」却不说明原因 [citation:3]。耗尽必须给人话失败原因。

### 2.2 FGS 合规（Android 14+ / 15+）

| 项 | 要求 |
| --- | --- |
| 类型申报 | Android 14+ 必须声明 `android:foregroundServiceType` 与对应 `FOREGROUND_SERVICE_*` 权限；`while-in-use` 类权限后台启动会失败，需按契约逐项核对 [citation:2][citation:18] |
| 类型选择 | 常驻 Linux 服务不天然属于 `dataSync`（6h 限）/ `shortService`（3min 限）/ `mediaPlayback` 等；按 `specialUse` 申报并准备上架说明，或按实际用途选用 `connectedDevice` [citation:8][citation:18] |
| 超时处理 | Android 15 部分类型有 24h 窗口累计超时，回调 `Service.onTimeout(int,int)` 后须在数秒内停止，否则 ANR [citation:18] → 实现 `onTimeout`：停服务 + 通知用户 + 保存盘状态，**不抛异常穿透 UI** |
| 后台启动 | Android 12+ 限制后台启动 FGS，需捕获 `ForegroundServiceStartNotAllowedException`，引导用户从可见状态启动 [citation:10] |
| 首启引导 | 一次性向导：电池优化白名单、厂商「睡眠名单」移除、开发者选项「停用子进程限制」（Android 14+ 可选）、充电与散热建议 [citation:3][citation:6] |
| 不承诺 | 不宣称 7×24 不中断；Doze / App Hibernation / OEM 策略属系统行为，只做如实提示 [citation:8][citation:10] |

### 2.3 Phantom process killer 治理

- Android 12+ 系统级 **32 子进程上限**，超额或后台高 CPU 直接 SIGKILL [citation:3]；
- 引擎侧：单会话进程数受控、禁止轮询式后台探测（UI 侧的 git poll / 状态轮询一律 `repeatOnLifecycle(RESUMED)` 作用域）[citation:3]；
- 客户机内由 `systemd`/`supervisord` 拉起的服务树计入子进程数，UML/QEMU 域需在启动前预估并给出「服务过多可能被系统杀」提示；
- 一旦被杀，走有界重启，不无限拉起。

## 3. 端口转发（`PORT_FORWARD`）

### 3.1 按域实现

| 域 | 机制 | 能力 |
| --- | --- | --- |
| **QEMU_VM** | QEMU SLIRP `-netdev user,...,hostfwd=tcp::8080-:80`；QEMU ≥7.0 已废弃 `-redir` [citation:19][citation:21]；Podroid 实现运行时**动态增删**转发规则、无需重启 VM [citation:11] | 完整入站映射；`::` 绑所有接口、单冒号仅 `127.0.0.1`（默认后者）[citation:19] |
| **UML_GUEST** | 真内核 + 独立网络栈 （Haven UML Guest）；宿主侧转发由引擎在宿主 socket 与客户机栈之间做用户态代理 | 支持高位端口映射；不支持 UPnP / STUN / 反向映射（SLIRP 类固有限制）[citation:19] |
| **PROOT_USERLAND** | 共享宿主网络栈，客户机进程直接 bind 高位端口，**无真正端口映射** | 仅「高位端口直绑」；`-p` 只能靠 userland-proxy，iptables NAT 不可用 [citation:20] → 声明 `PRIVATE_NETSTACK` 时必须拒 |

### 3.2 规则模型

```json
{
  "protocol": "tcp",
  "hostPort": 8080,
  "guestPort": 80,
  "bind": "127.0.0.1",
  "sessionId": "sess-7f3a2c",
  "owner": "abyss-plugin-phone-server"
}
```

| 校验 | 规则 |
| --- | --- |
| 低位端口 | `hostPort < 1024` → `E_PORT_PRIVILEGED`（普通应用不能绑）[citation:5][citation:15] |
| 冲突 | 宿主端口被其它会话/其它 App 占用 → `E_PORT_IN_USE`，不抢占、不静默换端口 |
| 绑定范围 | 默认 `127.0.0.1`；改 `0.0.0.0` 需用户二次确认 + 通知栏明示局域网可达 |
| 归属 | 规则绑定 `sessionId` + `owner`，会话关闭/插件卸载时整批释放 |
| 上限 | 单会话规则数上限（建议 ≤16），防规则风暴 |
| 动态 | 增删规则不重启会话；QEMU 走 monitor/HMP 更新 `hostfwd`，UML 走用户态代理表重建 |

### 3.3 公网可达边界

手机在运营商 NAT 后没有公网 IPv4，外网访问必须借内网穿透（frp / cloudflared）且需公网中转主机 [citation:14][citation:22]。**引擎只做到「本机 / 局域网可达」**，穿透配置属于消费方插件的可选入口，不在引擎职责内（`SRV-100 §7`）。

## 4. 资源隔离（常驻 vs 临时）

| 项 | 规则 |
| --- | --- |
| 会话分池 | 常驻会话池与临时构建会话池分开；`maxConcurrentExec=1` **按会话独立计**，不再全局共享 |
| 内存叠加 | UML 每会话固定 384MB，多会话叠加；UI 必须显示「N 个会话共占 N×384MB」（Haven UML Guest） |
| 盘配额 | 常驻会话的持久化盘（UML ~536MB ext4 / QEMU 2–64GB 稀疏盘）与临时构建工作区分账，共用 `defaultQuotaGb` 但独立记账 [citation:12]（Haven UML Guest） |
| 抢占 | 临时构建不得挤掉常驻服务的 FGS / WakeLock；资源不足时拒绝**新的临时会话**并给出「当前常驻服务占用 X MB」，不静默杀服务 |
| 优先级 | 用户显式停止常驻服务 > 系统 `onTimeout` > 临时构建资源申请 |
| CPU | 后台高 CPU 会触发 phantom killer，引擎对常驻会话的 exec 做速率限制并在通知栏显示负载 [citation:3] |

## 6. 降级链（修订 ARC-101 §6 / LIN-006 §6）

```
openSession(resident=true, domainHints=[UML_GUEST, QEMU_VM], PRIVATE_NETSTACK)
 ├─ 能力/签名/grant/端口/资源/FGS 资格 逐项校验，任一失败 → 人话错误码
 ├─ UML 可用            → READY（384MB / 10–20s / 近原生，服务器默认）
 ├─ UML 不可用
 │    ├─ QEMU 可用      → 需用户确认（≈200MB 引擎已在包内、镜像按需下载、≤180s）→ READY
 │    └─ 均不可用       → E_DOMAIN_NO_REAL_KERNEL，**不静默降到 PRoot**
 ├─ 底座插件内 PRoot 域（仅 L1/L2 服务）→ 只能高位端口直绑，UI 明示「无独立网络栈 / 无容器」
 └─ ptrace 被 ROM 拦截 → Shizuku uid2000 上下文重试；仍失败 → UNAVAILABLE + ROM 清单
```

| 纪律 | 说明 |
| --- | --- |
| 不假装 READY | 资产 / 探测 / FGS / 端口任一未绿，不返回 READY |
| 不静默换域 | 声明真内核能力时禁止降级到 PRoot |
| 不无限重启 | 有界退避，耗尽上报 |
| 平台限制如实上报 | Doze / FGS 超时 / OEM 保活 / 低端口 / 无公网 IP 均给可执行建议 |

## 7. M0 技术验证项（不阻塞架构裁定，但必须在写实现前闭环）

| # | 验证项 | 为什么必须 |
| --- | --- | --- |
| V-1 | **引擎 ELF 的加载路径**：`lib*.so` + `nativeLibraryDir` vs `system_linker_exec`（`/system/bin/linker64`）vs `targetSdk 28` 豁免，三选一并写进 CI | Android 10+ W^X 禁止私有可写目录 `execve` [citation:3][citation:7]；`linker64` 路径下需要 fork 子进程的工具（git / 包管理器 / popen）会被挡，需整条走 Shizuku `adb_shell` 兜底 [citation:9] |
| V-2 | JDK17 / SDK build-tools 中 `java` 等 ELF 打进 APK 还是经 loader 加载 | 唯一可能把 APK 推过 300MB 的变量；数据类（jar / 资源）走后续下载 |
| V-3 | 真机 FGS 类型申报在 Android 14/15 上的实际超时行为与 `onTimeout` 回调 | 避免上线后服务被系统静默停掉 [citation:18] |
| V-4 | Phantom process killer 在目标机型（含 Samsung One UI）上的子进程上限实测 | 32 子进程上限是系统级，服务树规模需据此定 [citation:3] |
| V-5 | UML 域的端口映射在任意 arm64 机型上的可达性（含 `127.0.0.1` vs `0.0.0.0`） | UML 有独立网络栈但宿主侧映射需自实现 （Haven UML Guest） |
| V-6 | QEMU `hostfwd` 动态增删在当前打包的 QEMU 版本上是否支持（≥7.0 语法） | `-redir` 已废弃 [citation:19][citation:21] |

## 8. 功能需求与验收

| FR | 需求 |
| --- | --- |
| FR-001 | 同一 `RuntimeSession` 引擎支持临时与常驻两种会话，靠 `resident` 分叉，不建第二套引擎。 |
| FR-002 | 常驻会话由 FGS + WakeLock 持有，通知栏常显并可一键停止。 |
| FR-003 | 崩溃重启有界（≤5 次、退避递增），耗尽返回 `E_RESTART_EXHAUSTED` 并给出可读原因。 |
| FR-004 | 实现 `onTimeout` 优雅降级，不抛异常穿透 UI。 |
| FR-005 | 端口规则按会话归属管理，关闭会话整批释放；`<1024` 一律拒绝。 |
| FR-006 | 声明 `PRIVATE_NETSTACK` 时禁止静默降级到 PRoot。 |
| FR-007 | 常驻与临时会话资源分池，`maxConcurrentExec` 按会话独立计。 |
| FR-008 | 不新增 AIDL 方法签名，现有 13 个 AIDL 与单测保持可编译。 |

| AC | 验收条件 |
| --- | --- |
| AC-001 | 关闭常驻会话后：`ps` 零残留、宿主端口释放、grant 撤销、FGS 通知消失、WakeLock 释放。 |
| AC-002 | 连续杀客户机服务 6 次，第 6 次触发 `E_RESTART_EXHAUSTED`，通知栏给出原因而非「重连中」。 |
| AC-003 | 常驻 UML 会话（384MB）与一次标准 Gradle 构建并存，构建完成后常驻服务未受影响。 |
| AC-004 | `hostPort=80` 被 `E_PORT_PRIVILEGED` 拒；`8080` 从宿主 `127.0.0.1` 可访问客户机 Nginx。 |
| AC-005 | 声明 `PRIVATE_NETSTACK` 但 UML/QEMU 均不可用时返回 `E_DOMAIN_NO_REAL_KERNEL`，不降级。 |
| AC-006 | 现有 `runtime-api` 模块单测全绿，AIDL 接口签名 diff 为空。 |
