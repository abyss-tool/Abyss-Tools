## 1. 目标与范围

检查 → 下载（镜像链 + 断点续传）→ SHA-256 强制校验 → 域白名单 → PackageInstaller 同签名安装；并拉取 changelog。

## 2. 现状锚点（克隆研究实测）

- `Abyss-Tools/core/update/src/main/kotlin/com/abyss/tools/core/update/UpdateManager.kt`
- `Abyss-Tools/core/update/src/main/kotlin/com/abyss/tools/core/update/ApkInstallGateway.kt`

> 研究口径：2026-11-21 对 `github.com/abyss-tool` 组织下 19 个公开仓库（主仓 / 发布仓 / 插件中心 / 13 归档插件仓 / 3 引擎级插件仓）全量拉取，共 511 个文件；主仓 296 个文件、约 22 个 feature 模块。

## 3. 功能需求

| 编号 | 需求描述（原子、可验证） |
|---|---|
| FR-001 | 摘要缺失即拒绝（不再有框架期兼容放行）。 |
| FR-002 | 下载前后双重校验 host，重定向落点复检。 |
| FR-003 | 下载体量上限与 zip bomb 三重上限复用 PatchEngine 防线。 |
| FR-004 | 安装前执行同签名门禁 + 发布者指纹硬校验。 |
| FR-005 | 未知来源确认页经系统 PendingIntent 转发，不触发后台活动启动限制。 |

> 纪律：每条 FR 必须至少被一条 AC 或一个自动化用例覆盖；下表 AC 为关键验收条件，完整覆盖关系由 `QA-008 需求追溯矩阵` 与 spec-lint 登记校验。需求变更需同步更新本文件与对应的测试夹具（`src/test/resources` 为通道契约镜像）。

## 4. 契约与接口

沿用宿主既有契约（`PluginContract.HOST_API_VERSION = 1`、`SemVer`、`UiState` 三态），本单元不新增跨模块接口。

## 5. 失败语义与边界

- 坏数据 / 非法版本 / 路径穿越 / 签名不符一律 fail-closed 拒绝并给人话错误，不猜测、不静默降级。
- 远端数据统一走 `UiState`（Loading / Error / Data），加载中禁止展示假数据。

## 6. 验收标准

| 编号 | 验收条件 |
|---|---|
| AC-001 | 下载被篡改 1 字节即校验失败并删除临时文件。 |
| AC-002 | 同签名校验不通过时安装被拒且给出人话错误。 |

> 验收方法：纯 JVM 单测（`./gradlew test`）/ CI 门禁脚本 / 真机回归清单（Android 15 与 16 各一台）/ 通道清单校验，按单元性质择一或组合。
