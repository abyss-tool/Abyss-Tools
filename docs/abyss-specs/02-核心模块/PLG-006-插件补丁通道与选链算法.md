## 1. 目标与范围

abyss-plugin-patches-v1：latest + patches[{from,to,url,sha256,sizeBytes,notes}]；updatablePatch 取 from 命中且 to 最大的补丁。

## 2. 现状锚点（克隆研究实测）

- `Abyss-Tools/core/plugin/src/main/kotlin/com/abyss/tools/core/plugin/PluginModels.kt`
- `abyss-plugin-app-builder/patches/index.json`

> 研究口径：2026-11-21 对 `github.com/abyss-tool` 组织下 19 个公开仓库（主仓 / 发布仓 / 插件中心 / 13 归档插件仓 / 3 引擎级插件仓）全量拉取，共 511 个文件；主仓 296 个文件、约 22 个 feature 模块。

## 3. 功能需求

| 编号 | 需求描述（原子、可验证） |
|---|---|
| FR-001 | latest 必须等于 plugin.json 的 version（CI 门禁）。 |
| FR-002 | 选链只允许 from 命中本机版本，禁止跨版本跳跃应用。 |
| FR-003 | 应用链路：下载 → SHA-256 → 备份 → 应用 → 失败回滚 → 版本账本随 plugin.json 升级 → PatchReport 摘要。 |
| FR-004 | 插件中心「一键检查更新」并发拉取全部已装插件的补丁通道，展示可更新徽章。 |

> 纪律：每条 FR 必须至少被一条 AC 或一个自动化用例覆盖；下表 AC 为关键验收条件，完整覆盖关系由 `QA-008 需求追溯矩阵` 与 spec-lint 登记校验。需求变更需同步更新本文件与对应的测试夹具（`src/test/resources` 为通道契约镜像）。

## 4. 契约与接口

```kotlin
@Serializable data class PluginPatchChannel(
    val schema: String = "abyss-plugin-patches-v1", val plugin: String,
    val latest: String, val patches: List<PluginPatch> = emptyList(),
    val rejectedPatches: List<RejectedPluginEntry> = emptyList())
```

## 5. 失败语义与边界

- 坏数据 / 非法版本 / 路径穿越 / 签名不符一律 fail-closed 拒绝并给人话错误，不猜测、不静默降级。
- 远端数据统一走 `UiState`（Loading / Error / Data），加载中禁止展示假数据。
