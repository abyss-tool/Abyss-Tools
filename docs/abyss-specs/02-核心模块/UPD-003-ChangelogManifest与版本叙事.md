## 1. 目标与范围

abyss-changelog-v1：latest 置顶 + history 下沉；设置页「更新日志」弹层渲染，markdown 与 notes 内容一致。

## 2. 现状锚点（克隆研究实测）

- `Abyss-Tools/core/update/src/main/kotlin/com/abyss/tools/core/update/ChangelogModels.kt`
- `Abyss-Tools-Release/changelog.json`

> 研究口径：2026-11-21 对 `github.com/abyss-tool` 组织下 19 个公开仓库（主仓 / 发布仓 / 插件中心 / 13 归档插件仓 / 3 引擎级插件仓）全量拉取，共 511 个文件；主仓 296 个文件、约 22 个 feature 模块。

## 3. 功能需求

| 编号 | 需求描述（原子、可验证） |
|---|---|
| FR-001 | 旧 latest 下沉 history，新版本置顶，history 不得丢失。 |
| FR-002 | markdown 与 notes 语义一致，渲染端按能力选择。 |
| FR-003 | changelog.json 的 versionName/versionCode 必须与 version.json 一致。 |
| FR-004 | 发布要点来自 docs/release-notes/v<版本>.md，一行一条。 |

> 纪律：每条 FR 必须至少被一条 AC 或一个自动化用例覆盖；下表 AC 为关键验收条件，完整覆盖关系由 `QA-008 需求追溯矩阵` 与 spec-lint 登记校验。需求变更需同步更新本文件与对应的测试夹具（`src/test/resources` 为通道契约镜像）。

## 4. 契约与接口

latest: { versionName, versionCode, tag, date, title, notes[], markdown, releaseUrl }
history: [ 同构条目 ]（v0.9.5 实测 20 条：0.7.0 → 0.9.4）

## 5. 失败语义与边界

- 坏数据 / 非法版本 / 路径穿越 / 签名不符一律 fail-closed 拒绝并给人话错误，不猜测、不静默降级。
- 远端数据统一走 `UiState`（Loading / Error / Data），加载中禁止展示假数据。

## 6. 验收标准

| 编号 | 验收条件 |
|---|---|
| AC-001 | 发布后 changelog.json 的 latest 与 version.json 严格一致。 |

> 验收方法：纯 JVM 单测（`./gradlew test`）/ CI 门禁脚本 / 真机回归清单（Android 15 与 16 各一台）/ 通道清单校验，按单元性质择一或组合。

**风险**
