## 1. 目标与范围

Loading / Error(message, retryable) / Data(value) 三态与 Result.toUiState() 扩展（详见 ARC-007）。

## 3. 功能需求

| 编号 | 需求描述（原子、可验证） |
|---|---|
| FR-001 | Error 默认 retryable = true。 |
| FR-002 | toUiState 的失败分支取 message，缺失时退化为异常类名。 |
| FR-003 | 禁止在 ViewModel 层自行构造假 Data 充当加载中。 |

> 纪律：每条 FR 必须至少被一条 AC 或一个自动化用例覆盖；下表 AC 为关键验收条件，完整覆盖关系由 `QA-008 需求追溯矩阵` 与 spec-lint 登记校验。需求变更需同步更新本文件与对应的测试夹具（`src/test/resources` 为通道契约镜像）。

## 4. 契约与接口

```kotlin
fun <T> Result<T>.toUiState(): UiState<T> = fold(
    onSuccess = { UiState.Data(it) },
    onFailure = { UiState.Error(it.message ?: it.javaClass.simpleName) })
```

## 5. 失败语义与边界

- 坏数据 / 非法版本 / 路径穿越 / 签名不符一律 fail-closed 拒绝并给人话错误，不猜测、不静默降级。
- 远端数据统一走 `UiState`（Loading / Error / Data），加载中禁止展示假数据。
