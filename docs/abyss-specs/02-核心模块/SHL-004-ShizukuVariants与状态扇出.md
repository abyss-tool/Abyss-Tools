## 1. 目标与范围

识别 Shizuku / Sui 等变体与授权状态；ShizukuMonitor 扇出，Compose 侧唯一桥接点 rememberShizukuStatus。

## 2. 现状锚点（克隆研究实测）

- `Abyss-Tools/core/shell/src/main/kotlin/com/abyss/tools/core/shell/ShizukuVariants.kt`
- `Abyss-Tools/app/src/main/kotlin/com/abyss/tools/ui/RememberShizuku.kt`

> 研究口径：2026-11-21 对 `github.com/abyss-tool` 组织下 19 个公开仓库（主仓 / 发布仓 / 插件中心 / 13 归档插件仓 / 3 引擎级插件仓）全量拉取，共 511 个文件；主仓 296 个文件、约 22 个 feature 模块。

## 3. 功能需求

| 编号 | 需求描述（原子、可验证） |
|---|---|
| FR-001 | 变体识别失败时保守标记为不可用，不猜测。 |
| FR-002 | 授权状态变化需实时通知所有功能页。 |
| FR-003 | 重启后状态需重新探测（Shizuku 通常需重新激活）。 |
| FR-004 | 独立 APK 插件的 ownAuth 状态与宿主状态分别维护，禁止继承假设。 |

> 纪律：每条 FR 必须至少被一条 AC 或一个自动化用例覆盖；下表 AC 为关键验收条件，完整覆盖关系由 `QA-008 需求追溯矩阵` 与 spec-lint 登记校验。需求变更需同步更新本文件与对应的测试夹具（`src/test/resources` 为通道契约镜像）。

## 4. 契约与接口

沿用宿主既有契约（`PluginContract.HOST_API_VERSION = 1`、`SemVer`、`UiState` 三态），本单元不新增跨模块接口。

## 5. 失败语义与边界

- 坏数据 / 非法版本 / 路径穿越 / 签名不符一律 fail-closed 拒绝并给人话错误，不猜测、不静默降级。
- 远端数据统一走 `UiState`（Loading / Error / Data），加载中禁止展示假数据。

## 6. 验收标准

| 编号 | 验收条件 |
|---|---|
| AC-001 | 撤销 Shizuku 授权后全部功能页在 1 次重组内切换为引导态。 |
