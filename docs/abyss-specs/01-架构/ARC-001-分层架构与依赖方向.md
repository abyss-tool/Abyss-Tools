## 1. 目标与范围

单向无环依赖：app → feature:* → designsystem → vendor:backdrop；feature → core:*；core:plugin → core:update → core:common。

## 2. 现状锚点（克隆研究实测）

- `Abyss-Tools/docs/ARCHITECTURE.md`
- `Abyss-Tools/settings.gradle.kts`

> 研究口径：2026-11-21 对 `github.com/abyss-tool` 组织下 19 个公开仓库（主仓 / 发布仓 / 插件中心 / 13 归档插件仓 / 3 引擎级插件仓）全量拉取，共 511 个文件；主仓 296 个文件、约 22 个 feature 模块。

## 3. 功能需求

| 编号 | 需求描述（原子、可验证） |
|---|---|
| FR-001 | 依赖方向单向，禁止 feature 之间互相依赖、禁止 core 反向依赖 app。 |
| FR-002 | core:plugin → core:update → core:common；core:plugin → plugin-sdk:plugin-api。 |
| FR-003 | core:shell 为 Android 库但指令编排（ShizukuCommands）零 Android 依赖可单测。 |
| FR-004 | 纯 JVM 模块（common / update / plugin / plugin-sdk）单测零 Android 依赖。 |
| FR-005 | vendor:backdrop 替换时只改 designsystem/glass 包，业务组件零感知。 |

> 纪律：每条 FR 必须至少被一条 AC 或一个自动化用例覆盖；下表 AC 为关键验收条件，完整覆盖关系由 `QA-008 需求追溯矩阵` 与 spec-lint 登记校验。需求变更需同步更新本文件与对应的测试夹具（`src/test/resources` 为通道契约镜像）。

## 4. 契约与接口

```
:app  MainActivity（引导门） · AbyssRoot（Crossfade 返回栈） · ServiceRegistry
  └─ :feature:*（纯 Compose，参数注入，不感知 DI 容器）
       └─ :core:designsystem ── :vendor:backdrop
       └─ :core:{plugin,update,shell,common} ── :plugin-sdk:plugin-api
```

## 5. 失败语义与边界

- 坏数据 / 非法版本 / 路径穿越 / 签名不符一律 fail-closed 拒绝并给人话错误，不猜测、不静默降级。
- 远端数据统一走 `UiState`（Loading / Error / Data），加载中禁止展示假数据。

## 6. 验收标准

| 编号 | 验收条件 |
|---|---|
| AC-001 | 新增模块的 build.gradle.kts 依赖图不出现环。 |
| AC-002 | CI 的 test 任务无需 Android SDK 即可运行纯 JVM 模块测试。 |

> 验收方法：纯 JVM 单测（`./gradlew test`）/ CI 门禁脚本 / 真机回归清单（Android 15 与 16 各一台）/ 通道清单校验，按单元性质择一或组合。

## 7. 依赖与风险

**依赖**

- `core:common`（SemVer / UiState / 渠道常量）

**风险**

- 无新增外部依赖；行为变更需回归既有单测。
