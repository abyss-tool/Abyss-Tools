## 1. 目标与范围

把「用户权限档位」从一句模糊的产品口径（普通 / 进阶 / 高级 / abyss-max / abyss-ultra）落成**可单测、可探测、可门禁**的工程模型：

1. **能力集合是唯一事实源**：`PrivilegeSnapshot.capabilities: Set<Capability>`，彼此正交，不做 ordinal 比大小；
2. **档位是派生标签**：`PrivilegeTier` 由 `TierCalculator.compute(capabilities)` 推导，只用于展示，**不用于功能放行**；
3. **功能门禁走超集判定**：`ToolDef.access.required ⊆ snapshot.capabilities`；
4. **多模式**：同一工具的降级 / 增强路径以 `ToolMode` 逐条声明，UI 如实展示「只读 / 执行 / 深度」。

**范围内**：`core:common` 纯 JVM 模型（`PrivilegeModels.kt` / `ToolAccess.kt` / `ToolCatalog` 27 条权限矩阵）、`:app` 探测层（`AndroidPrivilegeProbe` / `PrivilegeRepository`）、`core:shell` 的 Shizuku 展示性事实扇出、Manifest 组件声明（无障碍服务 / 设备管理员接收器）。
**范围外**：设备管理器能力面板本体（`N-DO-001`）、沙箱 Hook 层（`N-SBX-001`）、`ACCESSIBILITY` 的具体代点消费方 —— 本规格只提供探测与门禁底座。

## 2. 现状锚点（克隆研究实测，v0.10.1）

- `core/common/.../ToolCatalog.kt`：`ToolDef` 只有 id / title / category / status / pluginId / iconKey，**无任何权限字段**；
- `feature/dashboard/.../DashboardScreen.kt:161-178`：状态行只有 `StatusChip` 两枚 8dp 圆点（`Components.kt:74-88` 不渲染文字，文案仅进 `contentDescription`）—— 普通用户在首屏**读不到任何权限信息**；
- `DashboardScreen.kt:207-221` 快捷工具与 `NavHubScreen.kt:90-115` 全量 27 张工具卡：零门禁，点击直接进功能页；
- `core/shell/.../ShizukuShell.kt`：`ShizukuStatus.Running(version, authorized)` 无 `serverUid` / `suiAvailable` / 已装变体字段；
- `AndroidManifest.xml`：无 `BIND_ACCESSIBILITY_SERVICE` / `BIND_DEVICE_ADMIN` 声明，全仓 `AccessibilityService` / `DeviceAdminReceiver` 0 命中；
- 评审基线：PR #30 首版以「五档枚举 ordinal 比大小 + 每工具标 requiredTier」实现，存在 `Runtime.exec("id -u")` 误当 Shizuku root 探测、Dhizuku 以跨包组件态误判、移除 `ShizukuUi` 破坏既有调用点等问题 —— 本规格为其重做基线。

> 研究口径：2026-11-28 对 `github.com/abyss-tool/Abyss-Tools` main 分支 `0270053` 拉取核验。

## 3. 功能需求

| 编号 | 需求描述（原子、可验证） |
|---|---|
| FR-001 | `Capability` 枚举固定为 9 项正交能力：`SELF_BRANDING` / `ACCESSIBILITY` / `SHIZUKU_SHELL` / `SHIZUKU_ROOT` / `INSTALL_UNKNOWN` / `OVERLAY` / `APP_OBSERVE` / `DHIZUKU_ACTIVE` / `DEVICE_ADMIN_ACTIVE`，每项携带中文短标签与引导目标（`CapabilityGuide`）。 |
| FR-002 | 五档判定表（优先级 ULTRA > MAX > SENIOR > ADVANCED > BASIC，仅用于展示）：ULTRA = `SHIZUKU_SHELL ∧ DHIZUKU_ACTIVE ∧ DEVICE_ADMIN_ACTIVE`；MAX = `SHIZUKU_SHELL ∧ ACCESSIBILITY`；SENIOR = `SHIZUKU_SHELL`；ADVANCED = `ACCESSIBILITY`；其余 BASIC。`INSTALL_UNKNOWN` / `OVERLAY` / `APP_OBSERVE` / `SELF_BRANDING` **不升档**。 |
| FR-003 | **歧义裁决（定稿）**：ultra **不隐含**无障碍；max **不要求** `INSTALL_UNKNOWN`（缺失时徽章旁提示「待补 1 项」）；「设备管理员」= 本 App `DeviceAdminReceiver.isAdminActive`，Dhizuku 提供端是否为 DeviceOwner 由 `DHIZUKU_ACTIVE` 探测交叉验证表达。 |
| FR-004 | `PrivilegeSnapshot` 持有 `capabilities` / `shizuku: ShizukuFacet` / `reasons: Map<Capability, String>` / `environmentNotes` / `probedAtEpochMs`，并派生 `tier` / `has()` / `allows(required)` / `missing(required)`。 |
| FR-005 | `ShizukuFacet` 只承载**展示性事实**：`version` / `serverUid`（0=root / 2000=shell）/ `suiAvailable` / `installedVariants`（已装 ≠ 活跃）/ `variantHint`（措辞允许「疑似」）。**禁止**以包名硬判「当前活跃变体」，**禁止**以本地进程 `id -u` 推断 Shizuku 身份。 |
| FR-006 | `ToolAccess(required, modes, guideTarget)` 挂到 `ToolDef`，默认零权限向后兼容全部既有构造；`ToolCatalog.tools` 27 条逐条登记，新增工具漏填时 CI 单测 fail-closed。 |
| FR-007 | 探测层（`:app`）：无障碍走 `Settings.Secure` + `AccessibilityManager` 双路交叉（不一致保守判 false 并写 `reasons`）；设备管理员走 `DevicePolicyManager.isAdminActive`；Dhizuku 走 `Dhizuku.init ∧ isPermissionGranted ∧ dpm.isDeviceOwnerApp(provider)` 三方交叉；`INSTALL_UNKNOWN` / `OVERLAY` 走 `canRequestPackageInstalls` / `canDrawOverlays`。 |
| FR-008 | `PrivilegeRepository` 以 `StateFlow<PrivilegeSnapshot>` 为单一事实源；刷新时机 = Shizuku binder / 授权回调 + `ENABLED_ACCESSIBILITY_SERVICES` ContentObserver + `DeviceAdminReceiver.onEnabled/onDisabled` + `Activity.onResume`；**不跨会话缓存**。 |
| FR-009 | `Self_BRANDING`（图标 / 别名 / 主题等零授权能力）与 `APP_OBSERVE`（`QUERY_ALL_PACKAGES` 已在 Manifest）按真值登记，供门禁矩阵引用。 |
| FR-010 | `core:common` 零 Android 依赖：模型与判定可被 `./gradlew :core:common:test` 直接单测；Android 探测实现一律隔离在 `:app`，经 `ServiceRegistry` 手动装配。 |

## 4. 契约与接口

```kotlin
// core:common（纯 JVM）
enum class Capability(val label: String, val guide: CapabilityGuide)
enum class PrivilegeTier(val label: String, val summary: String)
data class ShizukuFacet(version, serverUid, suiAvailable, installedVariants, variantHint)
data class PrivilegeSnapshot(capabilities, shizuku, reasons, environmentNotes, probedAtEpochMs) {
    val tier: PrivilegeTier; fun has(c); fun allows(required); fun missing(required)
}
object TierCalculator { compute(caps); requirements; minimumTier(required); nextTier(current) }
data class ToolAccess(required: Set<Capability>, modes: List<ToolMode>, guideTarget: String)
data class ToolMode(name, required: Set<Capability>, note: String)

// :app
interface PrivilegeProbe { fun snapshot(): PrivilegeSnapshot }
class PrivilegeRepository(probe) { val snapshot: StateFlow<PrivilegeSnapshot>; fun refresh() }
object CapabilityGuideIntents { fun open(context, capability, shizukuStatus, onRequestShizukuPermission, onOpenShizuku): Boolean }
```

- `ToolDef` 新增字段 `access: ToolAccess = ToolAccess()`（默认值 → 既有 5 个 `ToolCatalogTest` 用例零改动）；
- `ServiceRegistry.privilegeRepository` 在 `init(context)` 装配，`MainActivity.onResume` 调 `refresh()`；
- `AbyssRoot` 参数增量：`privilegeSnapshot: PrivilegeSnapshot = PrivilegeSnapshot()`、`onOpenCapability: (Capability) -> Unit = {}`。

## 5. 失败语义与边界

- 任一探测异常一律 `runCatching` 吞为 false 并写入 `reasons[cap]`（人话原因），**绝不抛到 UI、绝不假装生效**；
- 无障碍双路不一致（在 Secure 设置里登记但服务未绑定）→ 判 false，`reasons = "无障碍已登记但服务未连接"`；
- Dhizuku `init` 失败（未装 / 未授权 / 提供端非 DO）→ false，`reasons` 按三类原因码给：未安装 / 未授权 / 提供端非设备所有者；
- Android 15+ 侧载受限设置、Android 16 高级保护：写入 `environmentNotes`，UI 显示「本机理论可达最高档」提示，不卡流程；
- 快照不跨进程缓存：Shizuku 重启掉档、无障碍被系统撤销、「仅本次」授权失效，全部靠监听 + `onResume` 重读 + 执行前二次校验三保险；
- 档位标签永远不参与放行：功能是否可用只看 `allows(required)`。

## 7. 依赖与风险

**依赖**

- `ARC-008` 纯 JVM 边界、`ARC-003` 手动 DI、`SHL-004` Shizuku 状态扇出
- `io.github.iamr0s:Dhizuku-API:2.5.3`（Maven Central，仅 `:app` 引入；公开 API `init` / `isPermissionGranted` / `requestPermission`）

**风险**

- Dhizuku 无「是否已激活 / 是否 DO」公开查询 API：主路径用 `init ∧ isPermissionGranted ∧ dpm.isDeviceOwnerApp(provider)` 交叉验证；提供端白名单可扩展（原版 `com.rosan.dhizuku` / Shevery `com.hamondev.shevery`）。
- `targetSdk` 钉 28 + Android 15/16 高敏权限收紧：无障碍须如实声明 `isAccessibilityTool="false"`，进阶档设计为可缺失档。
- Shizuku 变体不可硬判：`installedVariants` 只作展示，能力可用性靠执行前只读探针 + `checkRemotePermission` 兜底。
